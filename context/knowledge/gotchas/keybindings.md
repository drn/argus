## Key Bindings & Navigation

### Customizable keymap (`internal/tui/keymap`)

- **`internal/tui/keymap` is the single source of truth for argus's own rebindable keys.** `DefaultKeymap()` holds the built-in bindings (mirroring the old literals); `config.Keybindings` (context-scoped `[keybindings.<context>]` tables in config.toml) carries OVERRIDES ONLY. `keymap.Build(cfg.Keybindings)` overlays + validates; every dispatch site calls `Resolve(ctx, event) → Action`. Defaults do NOT live in `internal/config` (which returns an empty `Keybindings{}`).
- **The keymap RECOGNIZES the key; the runtime predicate stays in the dispatch switch.** Conditional/stateful interceptions (`ctrl+d`/Enter only when the session is dead; cmd-arrows zen-gated) keep their `if`-guards in `handleAgentKey` and `break`/fall through to the unchanged PTY tail (`tcellKeyToBytes`). Never push runtime state into the keymap — it's config-only.
- **`handleAgentKey` resolves twice and ordering is load-bearing.** The early interception block lists only the intercept actions; scrollback (`shift`+arrows/pgup/pgdn/end) ALSO resolves there but has no case, so it falls through to its position-sensitive block AFTER diff/file-panel routing — exactly as the literal dispatch did. Keep that split or scrollback will shadow diff/file modes.
- **Structural / failsafe keys are NOT rebindable and stay literal:** Esc/Enter/Tab/Backtab (modals, agent Esc-refocus + Enter-restart, settings Left→rail + Right/Enter-cycle, hera focus-ladder), `ctrl+c`/`ctrl+q`, and plain navigation keys (arrows AND pgup/pgdn/home/end). `bindingAllowed` rejects overrides onto these (and onto a bare rune in the `agent` context — it would steal PTY typing), keeping the default + logging a warning. A bad config never bricks the TUI.
- **Plain (unmodified) navigation keys are reserved in EVERY context** — not just plain arrows. `eventBinding` (the Resolve fast path) strips modifiers, so a plain `pgdn`/`home` binding in `rev` would also capture the `shift+pgdn` scrollback / `cmd`-modified variant. `bindingAllowed` rejects any `isModifiable` key with `Mods==0`.
- **Context-structural RUNES are reserved per context via `reservedContextKeys`:** diff `q` (exit) and settings `h`/`l` (focus rail/pane) are handled by a literal branch at the dispatch site, so an override onto them would be silently shadowed — `bindingAllowed` rejects them (keep default + warn) instead of letting the conflict happen.
- **`ctrl+z` has a hard SIGTSTP safety net in `handleAgentKey` independent of the keymap.** `agent.zoom` defaults to `ctrl+z` and is rebindable, but a literal `ctrl+z` (0x1a) must NEVER reach the PTY (it backgrounds the agent). After the interception Resolve block, an unconditional `if event.Key()==tcell.KeyCtrlZ { return nil }` swallows it — so rebinding zoom away from ctrl+z leaves ctrl+z inert, not a SIGTSTP leak. The swallow sits before diff/file routing (matching the historical literal placement).
- **Widget dispatch resolves the keymap for ALL key types, not just `KeyRune`.** The tasklist/filepanel/diff/settings handlers use `default:` (after the explicit structural arrow/Enter/Esc cases), so `ctrl+<letter>` and named-key overrides actually fire instead of being silently dropped. The tasklist filter-input guard (`if tl.filtering`) still sits ABOVE the switch, so filter typing is unaffected.
- **`Binding.Matches` is tcell-accurate:** rune bindings compare `Rune` (shift already baked into the rune — never test ModShift on a rune); `ctrl+<letter>` compares the named `KeyCtrlX` only (NOT rune+ModCtrl); modified arrows use the LOOSE `ev.Modifiers()&(ModCtrl|ModAlt) != 0` (cmd) / `&ModShift` test to match the iTerm2 mod-7 convention byte-for-byte. `ctrlKeys` maps letters to the named constants explicitly (a test pins it) because a tcell bump could renumber them.
- **Widgets read the keymap via a live accessor func (`Keys func() *keymap.Keymap`), not a one-shot setter.** App sets `tl.Keys`/`sv.Keys`/`heraPage.Keys = a.activeKeymap`; each widget's `keys()` falls back to `DefaultKeymap()` when nil (direct-construction tests). `activeKeymap()` rebuilds only when the `config.Keybindings` fingerprint changes (live reload without a per-keystroke rebuild); it runs on the tview goroutine, no mutex.
- **`HeraPage.isRailMutationKey` is DERIVED from the keymap** (`_, ok := keys().Resolve(CtxHeraRail, ev)`), no longer a hand-kept rune list — the CtxHeraRail action set excludes Enter + nav, so they correctly stay out.
- **The `?` help overlay is GENERATED from the keymap** (`modal.SectionsFromKeymap`), so it always reflects active overrides. Adding/changing a rebindable key means editing `keymap` (`defaultSpecs` + `actionLabels` + `contextOrder`), NOT the old hand-maintained `HelpSections` (removed). Structural rows + the plan-DAG / Modals sections stay as static `extra`/`staticHelpSections` in `help.go`.
- **Keybindings are config.toml-only — there are no DB-backed keybinding rows.** The old `keybindings.*` config rows were dropped; `migrate` sweeps stale ones (`DELETE ... LIKE 'keybindings.%'`, idempotent on every Open).

- **`modePluginView` fully surrenders the keyboard — argus reserves NOTHING but the double-Ctrl+Q failsafe.** Every key (Esc, Ctrl+C, `?`, tab numbers, modified arrows) returns the event so tview routes it to the focused pane. The ONLY interception is a fast double Ctrl+Q (`pluginFailsafeWindow`, 400ms): the first press is recorded in `a.lastCtrlQ` and forwarded; a second within the window intercepts (returns nil) and force-returns via `deactivatePluginView`. Two presses outside the window do NOT fire.
- **`a.lastCtrlQ` needs no mutex but MUST be reset in `activatePluginView`.** It's touched only on the tview main goroutine (via `SetInputCapture` → `handleGlobalKey`). Without the reset, a stale timestamp from a prior plugin view could trip the failsafe on the very first Ctrl+Q in a new view.
- **The failsafe window reads `a.nowFn` (defaults to `time.Now`).** Tests override it to drive the 400ms window deterministically — a real clock makes the double-tap timing flaky.
- **Esc exits the plugin view ONLY while `a.activePlugin.reconnecting` is true; when the plugin is live, Esc still forwards (full surrender).** During a reconnect the plugin is gone, so there's nothing to forward to — the `modePluginView` branch intercepts `KeyEscape` and calls `deactivatePluginView`. This check sits AFTER the help-overlay dismissal and BEFORE the Ctrl+Q failsafe. The double-Ctrl+Q failsafe still works in both states. Do not move the reconnect-Esc check above the help-overlay dismissal (a help frame can't appear while reconnecting, but the ordering documents intent).
- **The connector's unexpected-disconnect signal (`views.Connector.SetOnClose`) MUST be suppressed on an explicit `Close()`, or deactivate/failsafe would trigger a phantom reconnect.** `Close()` sets `explicitClose=true` BEFORE closing the socket (so the flag is visible by the time the blocked pump `Read`/`Write` unblocks), and `fireClose` checks it. `onClose` fires at most once across both pumps (`fireCloseOnce`). It runs on a pump goroutine, so `onPluginDisconnect` hops through `QueueUpdateDraw` and re-checks `a.activePlugin == m && m.conn == dropped` (ignores a stale drop from a replaced connection).
- **A reconnect resume reuses the existing resize/focus reconciler — `finishPluginReconnect` resets `connReady`(→true)/`focusSent`/`lastSent` but KEEPS `laidOut` true.** The pane never un-laid-out across a reconnect, so its post-layout rect is immediately authoritative and the first envelope on the new connection is the real size (never the 13x8 pre-layout default). `startPluginReconnect` flips `connReady=false` so the reconciler pauses while the socket is down (its target `m.conn` is the dropped connector). The redial loop runs on its own goroutine cancelled via `m.reconnectCancel`, which `deactivatePluginView` calls FIRST (before clearing `m.conn`) so a racing successful redial sees `reconnecting=false` and closes its orphan connection.
- **The reconnect backoff (`reconnectBackoff`) is a pure function of the attempt count (250ms→500ms→1s→2s steady), and the overlay message flip is driven by `a.nowFn` (grace `pluginReconnectGrace`=2min).** Both avoid wall-clock/random so tests are deterministic — never reach for `time.Now()` directly in the loop.
- **On resume, argus re-sends the resize envelope a second time after `a.resumeResizeDelay` (300ms; tests shrink it) via `scheduleResumeResize` — the immediate resize alone is NOT enough.** A warm-restarted plugin daemon (hera bounced via iris_reload) can render its first frame within ~35ms of the new WebSocket connecting — before it applies argus's initial resize — and then stays stuck at its default (tiny) size until the NEXT resize it processes (confirmed live 2026-06-11: argus logged the correct `316x78` on resume, but the pane rendered tiny and self-healed only on a manual terminal resize). The delayed re-send forces the reconciler past its dedupe (`lastSent=0` then `reconcilePluginViewSize`) so the plugin gets a resize after it has settled. The goroutine guards `a.activePlugin==m && m.conn==conn && !m.reconnecting` so a teardown or a second bounce within the delay window can't fire a stale re-send. A cold initial activation does NOT need this (the daemon is slow to first-frame, ~188ms, so the single initial resize lands first).
- **`internal/tui/keyenc` is the single source of truth for tcell-key → terminal-bytes.** Three sites used to carry divergent encoders (`terminalpane.eventBytes`, `streampane.eventBytes`, `app.go:tcellKeyToBytes`); the two pane encoders silently dropped arrows and ALL modifier combos, so a plugin could never bind Ctrl/Alt/Shift+arrow. They now all route through `keyenc.Encode`. The consolidation is **byte-identical** for the agent-PTY path — `keyenc_test.go` pins every legacy case so the agent view's typing didn't regress. Modified arrows use the xterm `CSI 1 ; <mod> <final>` form with `<mod> = 1 + Shift(1) + Alt(2) + Ctrl(4)`; Ctrl+Alt = mod 7, which iTerm2 maps Cmd+arrow onto and argus round-trips faithfully (no special-casing).
- **`keyenc` maps `tcell.KeyCtrlQ` → `{0x11}`.** This byte was ADDED during the consolidation (the legacy agent encoder lacked it) so a single Ctrl+Q forwards to a plugin under surrender. Safe for the agent view because `handleAgentKey` intercepts Ctrl+Q before the encoder ever runs.
- **`terminalpane.PasteHandler` MUST re-wrap pasted content in bracketed-paste markers (`ESC[200~`…`ESC[201~`) before forwarding to `inputBack`.** tview consumes the markers on argus's real terminal and hands `WrapPasteHandler` the *unwrapped* content; forwarding only the content makes a downstream tcell parser (a plugin's over the WS, e.g. hera's modal text fields) ingest the paste rune-by-rune — one full redraw per character. Re-wrapping once restores the framing so the consumer coalesces it into a single paste event. Wrap the WHOLE byte slice once before `send` (send does not chunk), so multi-line/large pastes stay framed with newlines intact. `terminalpane` is mounted ONLY by plugin views — argus's own agent panes use the separate `internal/tui/terminal` package — so this is safe (and also correct for any real PTY with bracketed paste enabled).
- **Plugin → argus control frames (`release`/`hotkeys`/`help`) arrive on the connector READ-PUMP goroutine, never the tview goroutine.** `dispatchPluginControl` decodes defensively (malformed/unknown → log + drop) and MUST route every tview/App-state touch through `a.tapp.QueueUpdateDraw`. The queued closures re-check `a.activePlugin == mount` because a release/failsafe can race between the read and the closure running. Do NOT touch tview directly from the `onControl` sink.
- **TEST gotcha: never nest a control-frame dispatch inside a `readUI`/`QueueUpdate` closure — it deadlocks.** `fake.onControl(...)` calls `dispatchPluginControl`, which itself calls `QueueUpdateDraw`; nesting that inside another queued closure waits on the same event loop and hangs. Call `fake.onControl(...)` from the test goroutine directly, then `syncUI(t, app.tapp)` to drain the queued work, then read state via `readUI`.
- **The plugin help overlay (`?` is plugin-triggered, NOT argus-reserved) is the ONE other key argus intercepts in `modePluginView` besides the failsafe.** The plugin sends `{"type":"help"}`; `requestPluginHelp` pops a `modal.NewHelpModalWith(title, pluginHelpSections(mount.hotkeys))` rendering the FULL dictionary (bar flag ignored) on the `pluginHelpPage`. While `a.pluginHelpVisible` is true, the `modePluginView` branch consumes exactly the NEXT key via `dismissPluginHelp` (checked BEFORE the Ctrl+Q failsafe) and returns nil — the overlay does not capture the keyboard beyond that single dismissal. `?` itself is never inspected by argus; it forwards to the plugin like any other key.
- **`deactivatePluginView` must `RemovePage(pluginHelpPage)` directly, not call `dismissPluginHelp`.** dismissPluginHelp refocuses `a.activePlugin`, which deactivate has already nil'd — so deactivate tears the page down inline and clears `pluginHelpVisible` to stop the overlay bleeding into the next plugin.
- **Plugin resize envelopes are sent ONLY by `reconcilePluginViewSize` on the tview goroutine — never from the dial goroutine.** A never-drawn `tview.Box` reports the 15x10 default rect, so computing the viewport before the first layout pass produced garbage 13x8 envelopes (shrank hera worker PTYs to 20x21 in production). The dial goroutine just flips `connReady` via `QueueUpdateDraw`; the afterDraw reconciler sends the first envelope from the real post-layout rect.
- **An envelope needs `connReady` AND `laidOut` both true.** `laidOut` is set in `afterDraw` only when the mount's page was the front page of the completed draw — `pane.GetRect()` must never be trusted before it. If the plugin pops its help overlay before the pane's first draw, the envelope (and focus) defer until the overlay is dismissed; that's intended, not a hang.
- **The reconciler re-sends whenever computed viewport != `lastSentCols/Rows` — on every draw, not just terminal resize.** This is the self-correction for a lost/raced initial envelope. A failed send leaves `lastSent` unchanged (retried next draw) and logs only the first failure of a streak (`sendFailLogged`) to keep a wedged conn from flooding ux.log. Re-activation zeroes `lastSent` to force a recovery re-send. All mount reconciliation fields are tview-goroutine-only; reset them in BOTH `activatePluginView` (fresh conn) and `deactivatePluginView` (mount reuse).
- **The focus envelope follows the FIRST successful resize on a connection (`focusSent`), so a plugin learns its size before it learns it has the keyboard.** If resize permanently fails the plugin never gets focus — acceptable, the conn is dead anyway.
- **The pre-layout viewport fallback is screen-minus-chrome (`pluginViewColOverhead`=2, `pluginViewRowOverhead`=4) and assumes the task-list layout** (1-row header + 1-row statusbar + pane border). Valid because plugin hotkeys only activate from `modeTaskList` (the agent view hides the header via `ResizeItem(a.header, 0, 0)`). If plugin activation is ever allowed from other modes, recheck these constants.
- **`ctrl+c` only exits from task list view.** In agent mode, writes `0x03` to PTY (or no-op if dead).
- **`ctrl+q` in diff mode must exit diff AND refocus terminal.** Otherwise user needs a second keypress.
- **`ctrl+d` exits agent view when session is dead.** Without this, Ctrl+D after agent exit is silently dropped.
- **`ctrl+l` opens fuzzy link picker (works while agent runs).** Uses `tcell.KeyCtrlL` — reliable across all terminals (unlike `ctrl+/` which has inconsistent encodings). Overrides the typical "clear screen" behavior; the agent PTY never sees it. Reads session log in a background goroutine; the `QueueUpdateDraw` callback must guard `a.mode == modeAgent` because the user may leave agent view during I/O.
- **`ctrl+r` in agent view opens the Claude session switcher and is intercepted before the PTY — this intentionally shadows Claude Code's own `ctrl+r` (transcript/verbose toggle) while focused on the agent terminal.** Same unconditional-steal pattern as `ctrl+l`. The agent never sees `0x12`. Note `ctrl+r` is also bound in the task list (`prune completed`) — different mode, no conflict. Backend-gated: a no-op with a "Session switcher is Claude-only" status notice for codex/pi (their sessions resume through different flags). Opens async (disk scan in a goroutine + `QueueUpdateDraw`), so the callback must re-check `a.mode == modeAgent && agentState.TaskID == taskID` because the user may leave during I/O.
- **`ctrl+k` in agent view opens the task switcher and is intercepted before the PTY (shadows readline `kill-line`/`0x0b`).** Same unconditional-steal pattern as `ctrl+l`/`ctrl+r`. Unlike the session picker, the switcher is built **synchronously** from `a.tasks` + `a.needsInputIDs` — both UI-thread caches the tick loop maintains — so there is NO background goroutine and therefore NO "user left agent view" `QueueUpdateDraw` guard. If task loading ever moves to disk/db I/O, add that guard. `TaskSwitcherModal.refilter` preserves input order, so the needs-input-first ordering is the *caller's* job: `openTaskSwitcher` sorts (needs-input → name → ID) before constructing the modal; the modal never re-sorts. The current task and archived tasks are excluded from candidates. Selecting mirrors `navigateAgentTask`: sync the task-list cursor with `tasklist.SelectByID` (so a later Ctrl+Q exits onto the switched-to task, not the one left behind) **then** `onTaskSelect(task, false)` — `autoStart=false`, so switching to a dead/finished task shows its pane without resurrecting the agent (unlike the task-list Enter path, which passes `true`). The modal closes (restoring `modeAgent`) *before* `onTaskSelect` re-enters.
- **`TaskSwitcherModal` has two render modes and the same widget backs the Ctrl+K switcher AND the Hera link/unlink parent picker — only the switcher opts into grouped mode.** `openTaskSwitcherModal` calls `SetGrouped(true)` (folder structure: tasks nested under collapsible project headers, task-list-style whitespace-split all-terms-substring search); the Hera picker (`herapicker.go`) leaves the default flat mode (single fuzzy list via `fuzzyMatch`, caller-preserved order). The `grouped` flag branches `refilter`/`SelectedTask`/`Draw`/`moveSelection` — don't assume `m.filtered`+`m.cursor` index the same thing in both modes (grouped: `m.cursor` indexes `m.rows`; `m.filtered` is only the flat match set used for count/empty checks). **Grouped auto-expand mirrors the task list's active section: exactly one project expanded at a time off-filter (all expanded while a query is active), and `autoExpandGrouped` rebuilds `m.rows` then MUST `restoreGroupedCursor` by task-ID/project identity — the rebuild shifts indices, so a raw index carry-over lands on the wrong row.** Every `prev`-index fallback (`skipUpGrouped`, `landOnLastTaskGrouped`, and the down-onto-header guard in `moveGroupedCursor`) routes through `clampToTaskRow`, which clamps the (possibly post-rebuild-stale) index into range and snaps to the nearest task row — the cursor must never strand on a header (Enter would no-op) or fall off the list. Needs-input ordering is no longer global in grouped mode (tasks scatter into their project folders, keeping only the per-row marker), matching the task list which never pins needs-input globally.
- **Switching sessions on a LIVE agent must reuse `pendingRerenderRestart`, not stop-and-restart inline.** `switchSession` persists the new `SessionID`, sets `pendingRerenderRestart[taskID]`, then calls `runner.Stop`; `handleSessionExitUI` does the actual restart once the async exit notification arrives. Restarting inline would race the exit callback (which would flip status / detach the pane against the freshly started session). Dead sessions skip this and call `startSession` directly. Because `SessionID` is set before the stop, the post-exit `CaptureSessionID` capture goroutine is skipped (it only fires when `SessionID == ""`), so it can't clobber the switch.
- **`ctrl+p` shells out to `gh pr view --web` in the current worktree.** No PR URL is tracked locally — gh discovers the PR from the branch + remote. Intercepted before PTY pass-through; the agent never sees `0x10`. No-op when `worktreeDir` is empty. `prOpener` is a package-level seam so tests stub the exec. From the task list (`modeTaskList` on the Tasks tab), uses the selected task's `Worktree` directly — no-op for pending tasks with no worktree yet.
- **Escape in agent view:** Refocuses terminal from diff/files but does NOT exit agent view. Always returns `nil` to consume the event.
- **Mouse clicks must update `agentFocus`, not just tview focus.** Custom `MouseHandler` overrides needed.
- **In diff mode: Up/Down switch files, j/k scroll diff.**
- **Cmd+Up/Down navigates between tasks in agent view** via `ModCtrl|ModAlt` check.
- **tcell has no `KeyCtrlLeft`/`KeyCtrlRight`.** Check `event.Modifiers()&(tcell.ModCtrl|tcell.ModAlt) != 0`.
- **`exitAgentView` must reset `header.SetTab(TabTasks)` and `statusbar.SetTab(TabTasks)`.** The global key handler routes non-agent keys based on `header.ActiveTab()` — if the tab isn't reset, up/down keys get routed to the wrong tab's handler (e.g., Settings) instead of the task list.
- **Settings `d` key is context-dependent: project rows → delete (with confirmation), backend rows → set default.** `handleDeleteOrDefault` dispatches on `currentSection()`. Deleting a project orphans its tasks (no FK constraint) — the confirmation modal counts tasks via `a.tasks` and warns the user.
- **Settings: `Left` from the pane ALWAYS returns focus to the rail — never overload it as "cycle backwards".** Value rows (spinner, agent-zoom, vault, plugin enum/bool) cycle on `Right`/`Enter` only (forward, wrapping). An earlier version also cycled on `Left`, which trapped the cursor in any category whose rows *all* cycle: the Appearance category is exactly spinner + agent-zoom, so there was no arrow-key path back to the rail (only the undiscoverable `h`, or `q` which quit the whole TUI). Keep `Left`/`h` = rail and `Right`/`Enter` = cycle so every category is escapable; if you add a new cycling row kind, do NOT wire it into the `KeyLeft` branch of `SettingsView.HandleKey`.
- **`ctrl+y` in agent view is ALWAYS intercepted, never falls through to the PTY.** With a payload staged, `copyStagedClipboard()` copies it and returns true; with nothing staged it returns false and the dispatch site (`ActAgentCopy` case) flashes a "Nothing to copy" notice via `flashNotice` instead — vim/emacs `yank-pop` no longer reaches the underlying program on ctrl+y (an intentional trade-off: the prior PTY fallthrough could paste back a stale in-CLI kill-ring entry unpredictably). The intercept fires synchronously on the tview goroutine; the actual pbcopy and clear-RPC run in goroutines. Mirrors the Hera view's `ctrl+y` trap (`internal/tui/hera/page.go`), which dropped the same `clipReady` gate.
- **`ctrl+z` in agent view toggles single-pane (zoom) and MUST be intercepted before the PTY.** `tcellKeyToBytes` maps `KeyCtrlZ` to `0x1a` (SIGTSTP); if it reached the PTY, Claude Code backgrounds the foreground task. `handleAgentKey`'s `KeyCtrlZ` case calls `toggleAgentZen()` and returns `nil` so the byte never forwards (same unconditional-steal pattern as `ctrl+l`/`ctrl+p`).
- **The resting agent-view layout is configurable via `ui.default_agent_zoom` (defaults true → zoomed).** `enterPendingAgentView`, `onTaskSelect`, `exitAgentView`, and App setup all call `applyDefaultAgentZen()`, which reads `db.Config().UI.DefaultAgentZoom` and dispatches to `setAgentZen()` (collapse left col + file panel to zero width) or `clearAgentZen()` (1:3:1). `clearAgentZen()` also runs from `toggleAgentZen`'s un-zoom branch. Note `ptySizeFromHostTerm` still seeds the initial PTY at FULL host width (`tw - agentViewColOverhead`) regardless of the configured default — when the default is split, the first draw lays out the 3/5 pane and the terminal pane's own `Draw()` recompute fixes the size on the next frame (one SIGWINCH repaint on entry, acceptable).
- **Zen mode collapses panes via `agentPanels.ResizeItem(item, 0, 0)`, not by removing them from the flex.** `setAgentZen` uses `(0, 0)`; `clearAgentZen` restores `(0, 1)` (the 1:3:1 proportions). Don't add a `screen.Sync()` — the terminal pane's `Draw()` recomputes PTY size from its own inner rect every frame, so the resize RPC + agent full-width repaint fire automatically (this is a real resize, not a ghost-cell artifact). Toggling does NOT touch `computePTYSize` (that path only seeds the initial size on agent-view *entry*).
- **`ctrl`/`opt`+`←`/`→` pane switching is gated on `!a.agentZen`.** When zoomed the side panels are collapsed to zero width, so switching focus to them would route keys to an invisible widget (the `→`-to-`focusFiles` case in particular silently swallowed input). The guard keeps focus on the terminal but still `return nil` (consumes the key) so the combo isn't forwarded to the PTY as a stray word-jump. Task navigation (`ctrl`/`opt`+`↑`/`↓`) is NOT gated — tasks aren't panes.
- **`setAgentZen` forces `agentFocus` back to `focusTerminal` when zooming.** The file panel is hidden at width 0; leaving focus there would route keys to an invisible widget. Un-zoom (`clearAgentZen`) keeps terminal focus (no prior-focus tracking). The restored un-zoom widths only lay out on the next draw, so verify restore behavior by reading `GetRect` after a `syncUI`, not synchronously.
- **The file-panel `e` opener (`editorArgv`) MUST keep the `--` separator before the editor argv in the tmux `new-window` args.** The `--` scopes only **tmux's own** option parse: without it, `tmux new-window` would treat a flag-laden `$EDITOR` (e.g. `code -w`) or a path beginning with `-` as tmux flags. It does NOT protect the editor's own arg parser — a worktree file literally named `-foo.go` still reaches the editor as `…/-foo.go`, which `vi`/`code`/etc. may misparse as a flag. That dash-prefixed-filename case is a pre-existing, accepted limitation (identical to the prior hardcoded-`nvim` opener), not something `--` fixes. `$EDITOR` is split on whitespace via `strings.Fields` (so `code -w` works; shell quoting is NOT interpreted) and falls back to `vi` when empty/blank. The build is a pure function precisely so the resolution can be tested without spawning tmux.
- **Hera tab (M6a) rail keys: `j`/`k` + Up/Down navigate, Space folds.** The rail's `InputHandler` only handles Down/Up/`j`/`k`/Space. Left/Right used to be OFF-LIMITS because `handleGlobalKey` ate them for tab switching; that arrow-key tab-cycling was REMOVED (it collided with horizontal navigation inside views) — **tab nav is now `1`/`2`/`3` only.** Left/Right now fall through to the focused view and are free for future rail/region navigation. The Tasks-tab `H` toggle (hide/reveal hera workers) and the `2`→Hera relabel are documented in tasklist-ui.md; the native Hera tab does not register a plugin hotkey, so it can't collide with the plugin-view full-surrender keyset.
- **Hera tab (M6c) rail mutation keyset + global-collision audit.** Rail-focus keys (handled by `HeraPage.handleRailMutation`, which the page's `FocusRail` branch calls BEFORE rail nav): `w` spawn worker, `r` rename, `a` archive-toggle, `P` pin-toggle, `s`/`S` status advance/revert, `Ctrl+D` delete, `Enter` enter-pane (restart dead session then `focus.Advance()`). While the rail's `/` filter is in INPUT mode, EVERY other rail mutation key is filter input (`handleRailMutation` bails early) — but `Enter` is special-cased: it selects the current filtered match, jumps into it (the SAME enter-pane logic), and clears the filter in one keystroke (BUG-028-RAIL) — see gotchas/hera-view.md. This is a deliberate, Hera-rail-only divergence from the Tasks-tab `/` filter's two-Enter (commit-then-navigate-then-reattach) convention; do not "fix" the Tasks tab to match, and do not re-introduce a two-Enter step here. Nav keys `j`/`k`/Up/Down/Space fall through to the rail; `Tab`/`Backtab`/`Ctrl+Q` are the focus ladder (handled by the page's top-level switch before the mutation handler). **`Ctrl+Alt+Left`/`Ctrl+Alt+Right` also walk the focus ladder** (Retreat/Advance, same as Backtab/Tab) so the rail↔coord↔agent regions are reachable with arrows; the page's top-level switch consumes them on the `Modifiers()&(ModCtrl|ModAlt) != 0` loose check (either modifier — matches the agent view's Ctrl+Alt+arrow pane switch) BEFORE forwarding a plain Left/Right to a focused pane's PTY. **Collision audit (while `mode==modeTaskList` on `TabHera`, the page is the focused primitive so unhandled global keys fall through to it):** `1`/`2`/`3` (tab switch) and `q` (quit) are consumed by `handleGlobalKey`'s rune switch BEFORE reaching the page — so they are NOT available as rail keys and tab-switching always works (`TestSmoke_HeraTabKeysDoNotBreakTabSwitch`). `?` opens the global help (which now lists the Hera section). `Ctrl+D`/`Ctrl+F`/`Ctrl+O`/`Ctrl+P`/`Ctrl+R` are gated on `ActiveTab()==TabTasks` in the global handler, so on `TabHera` they fall through to the page (only `Ctrl+D` is bound by the rail; the rest are unused there). `Ctrl+L` still Syncs (manual refresh, `mode!=modeAgent`). The native Hera tab registers NO plugin hotkey, so it can't collide with the plugin-view full-surrender keyset / double-Ctrl+Q failsafe. Left/Right are no longer consumed globally (tab nav is `1`/`2`/`3` only since the arrow-key tab-cycling was removed), so they now fall through to the page. New modal modes `modeHeraInput`/`modeHeraConfirm` are dispatched in the early modal chain so no global rune leaks while they're open.
