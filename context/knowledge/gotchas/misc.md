## Streampane Widget

- **StreamPane drops keystrokes when the input-back channel is full.** The widget's `send()` does a non-blocking `select` — matching the PTY writer backpressure pattern elsewhere in argus. Tests that pre-fill `back` and assert no drop will hang; assert "no panic / no second send" instead.
- **StreamPane `Touched()` increments only on non-empty chunks.** Empty chunks are a no-op so callers can poll the counter for damage without spurious redraws when the source feeds heartbeat-style zero-byte signals.

## Database Patterns

- **New columns use `ALTER TABLE ... ADD COLUMN ... DEFAULT ''` after `CREATE TABLE IF NOT EXISTS`.** Error for duplicate column silently ignored.
- **`taskColumns` is the canonical column list.** Update `taskColumns`, `scanTask`, `Add`, and `Update` in lockstep.
- **Backend default config must be self-healing.** `fixupBackends()` runs on every `Open()` to repair outdated configs. Any `DefaultConfig()` change must be mirrored there. All Claude fixup checks use `name == "claude"` (not `strings.Contains(command, "claude")`) to avoid matching user-created backends.
- **Claude permission flags are INJECTED at command-build time, not stored in the backend command.** `agent.BuildCmd` appends `config.PermissionModeFlags(cfg.Defaults.PermissionMode)` to the command — gated by `IsClaudeBackend` (positive check, NOT "not codex/pi", so bare/custom commands like a bash test backend never get Claude-only flags) and skipped when the command already names a permission flag (`hasPermissionFlags` → command wins, no double-inject). The default backend command is bare `"claude"`; `defaults.permission_mode` is **unconfigured by default and falls back to `bypass-active` (`--dangerously-skip-permissions`)** via `DefaultConfig`. `fixupBackends` does a one-time `stripPermissionTokens` of legacy baked flags and deliberately does NOT seed a config value — leaving the key absent so the launched command reverts to the bypass default (undoing the previously force-added plan mode). Don't re-add a force-append of any `--permission-mode`; the injection owns it now.
- **A new scalar config field touches four sites that must stay in lockstep.** Adding e.g. a `ui.*` key means: (1) the struct field + `toml` tag in `config.UIConfig` (or sibling), (2) the default in `config.DefaultConfig()`, (3) the loader entry in `db.Config()` (`stringFields`/`boolFields`/the optional-pointer block), and (4) the seed in `db.seedDefaults()` (`migrate.go`). Skipping (4) is silent — `db.Config()`'s absent-key fallback to the `DefaultConfig` value masks it on a fresh DB, so the only symptom is the raw `config` row being missing (and remote/`apistore.SetConfigValue` will reject the key unless you also add a `/api/settings` handler — intentionally omitted for TUI-local `ui.*` prefs; see `gotchas/remote-tui.md`). Mirror all four or a future reader copying one site as the canonical pattern will diverge.
- **Map lookups returning `*T` become non-nil interfaces.** `Get()` must check `if sess == nil { return nil }` before returning as interface.
- **`task_meta` cascade is asymmetric with archive.** `Delete` and `SetArchived(id, true)` wipe every `task_meta` row for the task; `SetArchived(id, false)` does NOT restore meta (there is none — the cleanup already ran at archive time). Same shape as `task_messages`. New cross-task tables that survive a task's lifecycle MUST hook both `Delete` and the on-archive leg of `SetArchived` or they accumulate orphan rows on the soft-archive path.
- **`ListMeta(taskID, namespace="")` returns every namespace.** The empty-namespace branch is deliberate (CLI introspection and the future Settings → Plugins audit view both want it); callers that need a single namespace must pass a non-empty string. The HTTP `GET /api/tasks/:id/meta?namespace=` query mirrors the same semantics — omitted means all.

## Go Patterns

- **Use `charmbracelet/x/term` for raw mode** (cross-platform). `TIOCGETA` is macOS-only, `TCGETS` is Linux-only.
- **`ansi.StringWidth` returns 0 for tabs.** Expand tabs before any width math.
- **Use `ansi.Hardwrap` not `ansi.Truncate` for wrappable content.** Cache wrapped lines; invalidate on content or width change.
- **Chroma resets after every token.** Use `injectBg(s, bgEsc)` to re-apply background after each `\033[0m`.
- **Keep daemon client test names short.** macOS Unix socket paths have 104-byte limit.
- **`filepath.Walk` must return error when root is inaccessible.** Check `err != nil && path == root`.
- **CRITICAL: Tests must NEVER operate on real `~/.argus/` paths.** All worktree paths and file operations in tests MUST use `t.TempDir()`. The `testGuard` in `internal/tui/worktree.go` is a last-resort safety net, but tests should be designed correctly.
- **Declare small enums with `uint8` underlying type, not `int`.** gosec G115 flags every `int → byte/uint8/uint16` conversion as overflow risk, even for ~5-value enums where it's provably safe. Declaring `type rowKind uint8` (vs `int`) lets `byte(r.kind)` and `uint64(r.kind)` pass lint without `//nolint` hints. Cost is zero — `iota` and enum semantics are identical. CI will reject the wrong choice on the lint step.
- **Reach for `hash/fnv` from stdlib instead of inlining FNV constants.** The canonical FNV-1a 64-bit offset is `14695981039346656037`; transcription errors are easy and silent (the hash still works, just isn't canonical, which fails review). `fnv.New64a()` plus `io.WriteString(h, s)` is shorter and self-documenting.
- **`dirCompletions` reads real `/tmp/` — tests that type paths there race with `t.TempDir()` from parallel tests.** Path autocomplete in `ProjectForm` opens its dropdown when matching directories exist, and Enter on an open dropdown calls `Accept()` which replaces the typed path. CI saw `TestProjectForm_TypeAndResult` flake when another test's `Test*` tmpdir matched the typed prefix. Tests that exercise the path field must use a path whose parent doesn't exist (e.g., `/no-such-dir-xyzzz123/test`) so `dirCompletions` returns nil and the dropdown stays closed.
- **`//nolint:linterX — explanation` is malformed.** golangci-lint splits the linter list on commas and treats everything after `:` (up to whitespace) as linter names — so an em-dash or freeform text after the linter name is parsed as a bogus linter and triggers a `unknown linters in //nolint directives` warning. Correct form is `//nolint:gosec // explanation` (literal `//` separator before the comment).
- **Test wall-clock windows ("wait Nms then check it didn't return") are flake-prone on loaded CI** — the goroutine being checked may not have run yet, producing a false positive. Wait for an actual signal (data arriving, channel close, state change) instead. Streaming code can shrink production timers via test-only `var` overrides (e.g. `sseKeepaliveInterval` in `internal/mcp/server.go`) so tests observe real data flow within tens of ms.
- **Don't mutate private server fields from tests just to wire up a shutdown path.** `s.httpSrv = srv.Config` (or similar) creates an implicit happens-before between `httptest.NewServer` setup and the handler goroutine that `-race` will eventually flag under different schedulers. Either drive the server through its own `ListenAndServe` (so it owns its bookkeeping) or test the cancellation contract (`Shutdown` cancels `shutdownCtx` → handler returns) without needing `httpSrv` set at all.
- **Any duration computed from `Task.StartedAt`/`EndedAt` must floor at zero.** Those are wall-clock (`time.Now`) timestamps persisted to the DB, so a backward clock correction (NTP resync after laptop sleep/wake) can leave `StartedAt` in the future or `EndedAt` before `StartedAt`. `time.Since`/`Sub` then return a negative `Duration` that rendered as "-2503s" / "-41h" across the tasklist, task-detail, MCP, and web SPA (all consume the pre-formatted `ElapsedString`). `model.Task.Elapsed()` is the single chokepoint and now clamps `d < 0 → 0`; route every duration display through it rather than subtracting timestamps inline. In-memory monotonic values (e.g. `app.recentStarts` keyed on a live `time.Now()`) are immune and need no guard.

## Codex Integration

- **`codex resume --last` is unreliable for multi-session.** Use `codex resume --dangerously-bypass-approvals-and-sandbox <session-id>`.
- **Session ID captured post-exit from `~/.codex/state_5.sqlite`.** The `_5` suffix is codex's schema version.
- **`fixupBackends()` migrates old codex flags** (`--yolo`, `--full-auto`) to `--dangerously-bypass-approvals-and-sandbox`.
- **`ensureTopLevel` must insert before the first `[section]` header, not append.** Appending a top-level TOML key to the end of a file places it inside the last section (e.g. `[notice.model_migrations]`), causing type errors. `ensureTopLevel` also migrates previously misplaced keys.

## Backend credential env mapping (env_vars)

- **`config.Backend.EnvVars` / the `backends.env_vars` JSON column hold the MAPPING ONLY (target env var → source descriptor), NEVER a secret value.** A secret value must never enter the DB, logs, fixtures, or git. `BuildCmd` resolves the source at spawn time through the swappable `agent.secretResolver` seam (default `envSecretResolver` = `os.LookupEnv`) and appends `target=value` to `cmd.Env`; an unresolved source sets nothing and `uxlog`s a warning naming ONLY the var, never the value. The success path logs nothing about the value.
- **Swap the resolver via `agent.SetSecretResolver` (returns the previous; nil resets to default) — never edit `BuildCmd` to add a new credential source.** This is the seam for a future `op`/1Password resolver.
- **The launchd-started daemon's minimal env will NOT carry the source (e.g. `HERA_OPENAI`)**, so the default `os.LookupEnv` resolver injects nothing there — same minimal-env constraint that once stripped `TERM`. Cross-vendor review works today only when the daemon is started from an env that already exports the source. The `codex` default seeds `{"OPENAI_API_KEY":"HERA_OPENAI"}`; `fixupBackends` fills it on pre-existing rows only when their mapping is empty (never clobbers a customized one).

## Model Selection (--model injection)

- **`--model` injection is scoped to known backend CLIs (claude, codex, pi).** Unknown/custom backends never receive the flag — if a custom backend needs a model, bake `--model` into its command. A backend command that already names `--model` always wins (no double injection), mirroring the `hasPermissionFlags` "command wins" rule.
- **Codex resume replaces the entire command string**, so `BuildCmd` must re-append the model flag itself — and flags must precede codex's positional session-id argument (`codex resume … --model X <session-id>`). The claude/pi resume paths append to the existing command, where the flag is already present.
- **Resolution is per (re)start, not per create:** `agent.ResolveModel` picks `task.Model` (per-task override) over `backend.Model` (settings default) at every session start, so editing a backend's default model in settings affects the next start/resume of every existing task without its own override.
- **`hera_spawn_worker`'s `model` arg is just `CreateInput.Model` threaded through (`mcp.HeraSpawnInput.Model` → `agent.HeraWorkerSpawnInput.Model`) — no separate injection logic.** It is backend-scoped — injected only for claude (opus/sonnet/haiku), codex (gpt-5…), and pi (the same `IsClaudeBackend || isCodex || isPi` guard as the bullet above) — and silently ignored when the worker's backend command already hard-codes `--model` (the `hasModelFlag` "command wins" rule above). Empty = backend default. The native Hera view spawn caller (`tui/heraactions.go`) leaves it zero-valued — there is no TUI model picker.

## Diligence profiles (resolution / loading / schema) — add-diligence-profiles

- **Profile resolution FAILS OPEN — a missing/invalid bound profile passes NO `--model`, never a hard error.** `agent.ResolveModel` → `resolveProfile` consults a profile ONLY when `task.Model` is unset AND `task.Archetype != ""`; the precedence is `task.Model → profile[archetype].model → project/backend default → "" (no flag)`. Any miss — no archetype (short-circuits before any disk I/O), profile missing/invalid (`ValidateName` errs), archetype unmapped in the profile, or the model not valid for the resolved backend (`backendAllowsModel`) — returns nil and falls through to `backend.Model`, uxlog'd, never failing the spawn. Empty model ⇒ `BuildCmd` injects no `--model` (the agent uses its own CLI default).
- **In-repo `.argus/profiles/<name>.toml` SHADOWS `~/.argus/profiles/<name>.toml` of the same name.** `profiles.Loader.locate` checks `RepoDir` (the worktree's `.argus/profiles`) before `LibraryDir` (`~/.argus/profiles`); the resolved `Profile.Source` reports which won (`in-repo` vs `library`), surfaced by `argus validate` and the Settings select-list. `Loader.Discover` enumerates BOTH dirs but de-dups by name (precedence is a Load-time concern, not a discovery one). `extends` overlays a child's *declared* fields (by `md.IsDefined`, so a zero-valued bool/int still overrides) onto the fully-resolved parent; an `extends` cycle is a Load error, aggregated by `ValidateName`.
- **Profile resolution + env-export run DAEMON-SIDE at spawn, NEVER inside the agent sandbox.** `resolveProfile` reads disk (profile TOML + the task row), which EPERMs from inside a sandboxed agent — so it runs in `BuildCmd` (daemon-side, outside the sandbox), and the outcome reaches the agent only as env: `ARGUS_PROFILE`/`ARGUS_ARCHETYPE`/`ARGUS_MODEL`, exported together or not at all (mirroring `ARGUS_TASK_ID`), and omitted entirely on any fall-open. An agent must NOT read `~/.argus/profiles/` itself — only the env (or its own in-repo `.argus/profiles/`, which lives inside its worktree). The in-repo hera skill §9 documents the read side.
- **`[panel]` is an OPAQUE forward-reference seam — validation checks STRUCTURE only, never grammar, and nothing consumes it yet.** `profiles.Profile.Panel map[string]any` is retained verbatim (`PanelPresent` ← `md.IsDefined("panel")`); `Validate` does NOT interpret reviewers/lenses/synthesizer — that grammar is owned by the sibling `2a-xvendor-review` capability. The README, the `customer_grade` seed comment, and the in-repo hera skill all explicitly defer panel consumption to 2a; reconciliation when 2a lands is contained to that one field's validation + a consumer.
- **Three plain schema columns back profiles — all default/nullable adds, no migration shim (single-user policy).** `tasks.archetype TEXT NOT NULL DEFAULT ''` (the authoritative resolution key `ResolveModel` reads), `projects.profile TEXT NOT NULL DEFAULT ''` (the project→profile NAME binding — the body is NEVER stored, there is no profiles table; empty ⇒ resolves `default`), and `hera_roles.archetype TEXT` (a planned node's intended archetype, mirrored onto the live role for display and copied into `CreateAndStart` by the gater at materialization). Existing rows read empty/NULL ⇒ no archetype / unbound ⇒ resolve via defaults / fall open. The `tasks`/`hera_roles` adds are idempotent `ALTER TABLE … ADD COLUMN` for existing local DBs.

## Cross-vendor review panel (add-cross-vendor-review)

- **Fable (`claude-fable-5`) reliably runs only at LOW effort in the argus/Workflow harness — at HIGH it ALWAYS falls back to Opus, at MEDIUM intermittently.** A `[panel]` (or any spawn) that names a Fable finder at high/medium effort will *silently review with Opus* (`workflowProgress.fallbackModel=claude-opus-4-8`; the transcript shows a `fallback_message` + `claude-opus-4-8` model), corrupting the diversity assumption and cost accounting. Pin Fable finders to `low`. Detect a fallback by grepping the agent transcript for `claude-opus-4-8` / `fallback_message`, not by trusting the requested config.
- **You CANNOT measure cross-vendor decorrelation with a single-vendor answer key.** A key built from Anthropic-lineage (Opus/Fable) reviews structurally cannot credit a foreign model's distinct catches, so it always ranks a same-lineage tier above the foreign model regardless of what the foreign model actually finds. The validation key MUST pool every vendor's findings and adjudicate from code evidence. (PR-45 slice: codex's distinct cross-tenant finds landed entirely as out-of-key "extra-real".)
- **Cross-vendor comparisons require packet symmetry — every reviewer must see the identical code.** On the PR-45 slice, codex appeared to *uniquely* catch the two highest-value bugs only because the Anthropic reviewers had been denied the runtime endpoint + RLS-migration files; once all reviewers got the same broad packet, both bugs were caught 5/6 and codex added zero unique key catches. Scope asymmetry manufactures false decorrelation.

## Pi Integration

- **Pi's argv parser has no `--` end-of-flags separator.** `pi -- "<prompt>"` consumes `--` as an unknown flag and pairs it with the next arg. `BuildCmd` passes the prompt as a bare positional argument for pi only; other backends still use `--`.
- **Pi treats `@<token>` as a file include and unknown `-<token>` as an error.** This is pi's documented behavior, not a bug — prompts starting with `@` will include that file. Prompts starting with `-` will fail in pi.
- **Pi has no `--session-id` flag for new sessions.** Like codex, pi mints its own UUID and Argus captures it post-exit via `CapturePiSessionID`. Resume uses `pi --session <UUID>` (partial UUIDs accepted).
- **Pi session UUID lives in the filename, not stdout.** Files are at `~/.pi/agent/sessions/--<encoded-cwd>--/<timestamp>_<uuid>.jsonl`. `piEncodeCwd` must mirror pi's `getDefaultSessionDir` exactly: strip ONE leading `/` or `\` (single-char, NOT a TrimLeft), then replace remaining `/`, `\`, `:` with `-`, wrap in `--…--`. Adjacent special chars produce adjacent dashes (e.g. `C:\` → `C--`).
- **Sandbox must allow writes under `~/.pi`** (mirroring the `~/.codex` rule). Without it, pi sessions are silently dropped under macOS sandbox and `CapturePiSessionID` always returns "no session files" → resume permanently broken. Pinned by `TestSandbox_PiBackendWritable`.
- **Daemon mode must capture post-exit session IDs too.** Both codex and pi mint UUIDs internally; the TUI's `handleSessionExitUI` and the daemon's `onFinish` both call `agent.CaptureSessionID`, which dispatches to the backend-specific scan. Without the daemon-side capture, headless / PWA-only users can never resume codex or pi tasks.
- **Backend commands have no UI editor.** Backends CRUD exists on REST (`/api/backends`, master-token only — a command template is RCE-equivalent), but neither the TUI settings nor the PWA exposes command editing; the TUI settings edits only the default backend (`d`) and the per-backend default model (`m`), and the PWA's backends list is display-only. `fixupBackends` inserts any defaults missing from existing DBs on every Open so new backends propagate without a schema bump — pinned by `TestFixupBackends_InsertsMissingDefault`.
- **Pi requires a local ollama daemon + `qwen3:32b` warmed before exec.** `Runner.Start` calls `agent.EnsurePrelaunch` before `BuildCmd`; for pi backends, that runs `ollama.EnsureRunning` (probe → `brew services start ollama` → `POST /api/generate keep_alive=30m`). Failure short-circuits Start so the task never half-launches.
- **Don't `exec.Command("ollama", "serve")` from the Argus daemon.** A daemon-forked `ollama serve` panics during Metal init with `ggml_metal_init: failed to create command queue` because the macOS GUI session's Metal context isn't reachable from a non-GUI process tree. Launchd-managed ollama (via `brew services` or `Ollama.app`) gets the right context. The `ollama.brewCmd` package var encodes this — don't reach for a direct fork as a fallback.
- **`cmd.WaitDelay` is required when `cmd.Stdout = &bytes.Buffer{}`.** Without it, `cmd.Run()` blocks on the I/O goroutines for as long as ANY child process inherits the pipe FD — even after a context-cancel SIGKILL on the leader. `ollama.StartDaemon` sets `WaitDelay = 500ms` so the prelaunch timeout actually fires. Pinned by `TestEnsurePrelaunch/pi_backend_respects_timeout`.
- **`Runner.Start` is the single chokepoint for prelaunch hooks.** Every launch path — `CreateAndStart`, daemon RPC `StartSession`, kick-restart — funnels through `Runner.Start`. Putting the hook there means new-task creation, resume, and restart all get the same pre-flight. Don't duplicate the hook in `CreateAndStart` or you'll double-block.
- **Prelaunch resolution errors are swallowed.** If `ResolveBackend` fails inside `EnsurePrelaunch`, the helper returns nil — `BuildCmd` will surface the actual "no backend configured" error a few lines later. This avoids double-erroring on the same condition.
- **`ollama.EnsureRunning` is serialized by `ensureMu`.** Without it, two concurrent pi-task launches would both shell out to `brew services start ollama` and both block up to 5min preloading the same model. With the mutex, the second caller waits for the first to finish, then runs through quickly (daemon up, model already loaded). Pinned by `TestEnsureRunning/concurrent_callers_serialize`.
- **`Runner.shutdownCtx` is cancelled by `StopAll` before stopping sessions.** The prelaunch hook (`runner.Start` → `ensurePrelaunchFn(r.shutdownCtx, …)`) listens on it so daemon SIGTERM unblocks an in-flight cold model load (otherwise the daemon's `cleanup()` would sit on the full 6-minute prelaunch budget waiting for ollama). Pinned by `TestRunner_StopAll_CancelsPrelaunchCtx`. After `StopAll`, the Runner should not be reused for new Start calls — the cancelled ctx will fail every prelaunch.

## Knowledge Base & MCP

- **FTS5 doesn't support UPDATE.** Upsert = DELETE+INSERT in transaction.
- **FTS5 `SanitizeQuery` must strip all operators:** `" * ( ) : ^ { } - +`.
- **FTS5 + metadata JOIN avoids N+1 under mutex.** Never issue per-row `QueryRow` inside `rows.Next()` while holding `d.mu`.
- **MCP server echoes client's `protocolVersion`** — Codex workaround.
- **All config file writes should be atomic** (temp + rename).
- **KB Indexer started/stopped by daemon.** Start after MCP, stop before MCP shutdown.
- **Incremental scan compares mtime at unix-second granularity.** Sub-second edits within the same second are missed until the next fsnotify event or daemon restart. The TOCTOU window between `KBMetadataMap()` and fsnotify watcher start means changes during scan are also deferred.
- **`KBMetadataMap` must check `rows.Err()` after iteration.** A partial result without error check causes `IncrementalScan` to delete documents that weren't returned due to mid-stream DB errors.
- **Claude Code MCP entries require `"type": "http"`.** A bare `{"url": "..."}` entry in `mcpServers` fails to parse. Must be `{"type": "http", "url": "..."}`. The JSON key is `"type"`, not `"transport"` (which is the CLI flag name).
- **MCP config is injected globally only (`~/.claude.json`, `~/.codex/config.toml`), not per-worktree.** Per-worktree `.mcp.json`/`.codex/config.toml` injection was removed — it polluted git status in every project and was redundant since global config applies everywhere.
- **MCP `instructions` field in `InitializeResult` is truncated at ~2KB by Claude Code.** Put the most critical rules first. The `kb_ingest` tool description intentionally duplicates key rules from `kbInstructions` because not all MCP clients surface server instructions at tool-call time.
- **MCP Streamable HTTP `GET /mcp` must hold the SSE stream open** until client disconnect or server shutdown. Clients like Codex `rmcp` open this stream right after `initialize` and report "Transport channel closed" if it ends. The handler emits `: keepalive\n\n` SSE comments every 30s to defeat idle-connection timeouts. Argus opts Codex into rmcp via `experimental_use_rmcp_client = true` (`internal/inject/codex/codex.go`), so the long-lived GET is mandatory, not optional.
- **MCP `Server.Shutdown` must cancel its own context before `httpSrv.Shutdown`.** Otherwise long-lived GET/SSE handlers block on their request context and `http.Server.Shutdown` waits for them indefinitely. The `shutdownCtx` cancellation path is what makes shutdown actually finish.
- **JSON-RPC notifications (no `id` field) over POST `/mcp` must return `202 Accepted` with an empty body**, not a JSON-RPC response with `"id": null`. Detect notifications by probing the raw body for `"id"` presence — `json.RawMessage`/`interface{}` can't distinguish `"id": null` from absent. Strict clients reject malformed null-id responses.
- **`toolDefs` slice must be copied before append in `handleToolsList`.** The package-level `var` could be corrupted if `append` reuses its backing array when adding task tools.
- **`Set*` wiring on `mcp.Server` must complete before `ListenAndServe`.** Fields like `s.taskDB`, `s.schedDB`, `s.schedRunner` are read at request time without a mutex — happens-before is guaranteed only by the daemon init order. When adding a new conditional tool family (e.g. `schedule_*`), the dependency it wraps must be constructed before the MCP block in `internal/daemon/daemon.go` so `SetXxxManager` can be called pre-listen. Reordering a later block (scheduler/pushMgr) up to before the MCP block is the standard fix.

## File Explorer

- **`autoExpand` must only treat `indent == 0` dirs as expandable.** Synthetic sub-dir rows (indent > 0, IsDir) are display-only groupings from `buildChildTree`. Without the `row.indent == 0` guard, navigating onto a sub-dir row collapses the top-level parent, causing all children to disappear.
- **`CursorUp` must track `wasChild` BEFORE decrementing to distinguish entering vs exiting a folder.** `wasChild = fp.rows[fp.cursor].indent > 0` captures whether the cursor is inside a folder pre-move. Without this, `skipToLastChild` traps the cursor inside the folder when navigating up from the first child (it re-enters instead of exiting).
- **`buildChildTree` groups flat file paths into a trie and emits dirs-before-files at each level.** Sub-directories are always expanded (no interactive collapse). Only top-level directories (indent 0) toggle via `autoExpand`.
- **`skipToLastChild` scans all nested indent levels, not just immediate children.** It finds the last non-directory row before the next `indent == 0` boundary. For deeply nested trees, this lands on the deepest last file.
- **`CursorUp`/`CursorDown` must not `skipToFile` when `awaitingFetch` is true.** When `autoExpand` returns a non-empty fetch string and the cursor is on a dir row, the dir's children haven't arrived yet. Calling `skipToFile` skips over all stacked unfetched directories to the nearest file — e.g., pressing up from below 3 closed dirs jumps past all of them. The `awaitingFetch()` helper guards both directions.

## Fork Context Capture

- **PTY session logs contain `\r` (carriage return) characters that must be normalized before filtering.** Claude Code uses `\r` to overwrite status indicators in-place. Without `\r→\n` normalization, multiple screen elements concatenate on one "line" and per-line noise filters fail to match.
- **PTY session logs contain `\u00a0` (non-breaking space) that must be normalized.** Claude Code uses NBSP in tool result formatting. Without normalization, `\s+` patterns may not match as expected.
- **Long terminal lines (>120 bytes) need inline noise stripping, not just per-line filtering.** VT cell rendering concatenates the content area, status bar, separators, and prompt onto a single line with whitespace padding. `cleanLongLine` removes these inline patterns before per-line `isNoiseLine` runs.
- **Modal typeahead AC must NOT open when its field is not focused.** Two variants: (1) Calling `updateProjectAC()` in the constructor opens the dropdown immediately when input is pre-filled. (2) Async `SetBranchOptions` callback triggers `updateBranchAC()` while focus is on the prompt field — the pre-filled branch text matches itself, opening the dropdown. Fix: `updateBranchAC` gates `branchACOpen` on `f.focused == ntFieldBranch`. General rule: any `update*AC()` that sets `*ACOpen = true` must check that the corresponding field is focused.
- **`onProjectChanged()` must call `loadSkills()`.** Skill autocomplete depends on the selected project's `.claude/skills/` directory. Without reloading in `onProjectChanged`, the Enter and Down-arrow non-AC paths leave stale skills cached from the previous project. `projACAccept` delegates to `onProjectChanged` — don't duplicate the call.
- **Plugin skill discovery must follow symlinks and read `installed_plugins.json`.** Claude Code plugins ship `skills/` as a symlink into the marketplace checkout, so `filepath.WalkDir` silently skips them unless the root is resolved via `filepath.EvalSymlinks` first. Plugin names come from the manifest key (`<plugin>@<marketplace>`), not the cache directory layout. Skill IDs come from each SKILL.md's `name:` frontmatter field, not the containing directory — nested paths like `skills/merchant/font-licensing/SKILL.md` still expose a flat `<plugin>:<name>` ID.
- **`FilterSkills` is a case-insensitive substring filter, not a prefix match.** Mirrors Claude Code's slash-command picker: `/rev` matches both `review` and `cortex:review`. Both the TUI's `updateAutocomplete` and the PWA's `updateAC` rely on this so plugin-namespaced skills (`<plugin>:<name>`) surface from the bare name the user is most likely to type. Don't switch back to `strings.HasPrefix` thinking it's "more predictable" — it hides plugin items behind their plugin prefix.
- **PWA new-task AC: trigger is the token at the cursor, not the start of the prompt.** `updateAC` reads `promptEl.selectionStart`, walks left/right to whitespace, and treats that token as the trigger candidate. If the trigger were `val.startsWith('/')`, the AC would never open mid-prompt — broken for prefilled prompts (share target, dictation) and for users who write context first then add `/skill`. `selectAC` must replace exactly `[acTokenStart, acTokenEnd)` so leading text isn't clobbered. Cursor moves via mouse/arrow don't fire `input`, so AC also subscribes to `click` and `keyup` (filtered to Left/Right/Home/End — ArrowUp/Down would clobber `acIdx` while navigating the dropdown).

- **MCP task tools use the same `TaskCreator` injection pattern as the API.** `SetTaskManager()` wires in the creator, querier, and stopper after construction — the same circular-import-avoidance pattern. Task tools only appear in `tools/list` when `taskMgmtEnabled()` confirms all three deps are non-nil.

Longest-match wins across siblings.
- **MCP `task_archive` mirrors the TUI 'a' keybinding — archiving is independent of `Status`.** `/archive` does not set `StatusComplete`.

## Remote API

- **API server cannot import `daemon` package (circular import).** It uses `HeadlessCreateTask` from `daemon`, but `daemon` imports it. Fix: inject a `TaskCreator` function via closure at daemon wiring time, breaking the cycle.
- **Headless task creation uses default 24x80 PTY dimensions.** Agents format initial output for the PTY size at launch. The TUI resizes the PTY when a user opens the agent view, so headless tasks auto-correct on attach.

## Scheduled Tasks

- **A brand-new schedule must not fire on the first tick.** `Scheduler.tickOne` only fires when `NextRunAt` is set and has passed; on the first tick it just computes `NextRunAt` and persists. Otherwise saving an `@every 1m` schedule would spawn a task the same second the user clicks Save. The first fire is always one cron interval after creation.
- **Disabled schedules still get `NextRunAt` updated.** The web/TUI surfaces preview the next-fire time even for off rows so the user can sanity-check before flipping the toggle. Skip this and the row shows a stale value forever.
- **`Scheduler.fire` reloads the row after `db.UpdateSchedule`.** It writes `LastRunAt`/`NextRunAt`/`LastTaskID`, then the surrounding `tickOne` reads the row again before falling through to the "compute next-run" branch — without the reload, the in-memory copy is stale and `tickOne` would overwrite the post-fire bookkeeping.
- **Per-fire task names include a timestamp suffix.** `agent.CreateAndStart` auto-suffixes name collisions with `-1`, `-2`, …, but a schedule that fires every minute would walk that counter forever. Suffixing with `name + "  YYYY-MM-DD HH:MM"` makes each fire a fresh worktree path.
- **The cron parser is `robfig/cron/v3` `ParseStandard` (5-field only).** 6-field (seconds-precision) expressions are rejected — Argus treats minute as the smallest unit because the scheduler ticks at one-minute intervals. Don't add `cron.Second` to the parser flags or the UI hint string in the schedule form will lie.
- **API `PUT /api/schedules/{id}` is a partial update.** All fields are pointer-typed in the request struct; nil means "leave alone". The toggle-enabled UX in the SPA depends on this — sending `{"enabled":false}` must not blank the prompt or schedule.
- **`PUT /api/schedules/{id}` recomputes `NextRunAt` anchored on `LastRunAt` only when non-zero.** `cron.Schedule.Next(time.Time{})` returns a year-0001 date which the scheduler tick reads as "due now" and would fire the schedule on the very next tick — exactly what the "no first-tick fire" invariant forbids. When the schedule has never fired (`LastRunAt.IsZero()`), anchor on `time.Now()` instead.
- **The TUI's manual run-now path must use `scheduler.FireName(name, now)`, NOT `name + " (manual)"`.** Rapid double-clicks on Run Now would otherwise hit a worktree-name collision (`agent.CreateAndStart` auto-suffixes with `-1`, `-2`, …) instead of being naturally disambiguated by the timestamp. The format also has to match `scheduler.fire()` so manually-fired and automatically-fired tasks render identically in the task list.
- **`scheduler.fire` callers MUST hold `fireMu`.** Without it, `RunNow` from an HTTP goroutine can race with the per-minute `tick()` and double-fire the same row: the tick reads the schedule, RunNow fires + persists fresh `NextRunAt`, then the tick resumes its loop with the stale copy and fires again. `tickOne` must also re-read the schedule under `fireMu` and re-check `NextRunAt > now` before calling fire.
- **A schedule carries an optional per-schedule model override (`ScheduledTask.Model`), threaded to the fired task via `scheduler.TaskCreator`'s `taskModel` arg → `HeadlessInput.Model` → `agent.ResolveModel`.** Empty = the backend's configured default (the prior behavior). The override must reach `create()` at fire time — like `Backend`, it can't be set post-creation because `agent.CreateAndStart` resolves the model inside its transactional flow before `fire()` sees the task row. The TUI schedule form exposes Model as **free-text** (not a per-backend cycling selector like the new-task form) so any unlisted model is reachable; the SPA modal mirrors the new-task per-backend select + custom-input.

## Task Auto-Naming (Haiku)

- **Auto-rename never touches `task.Worktree` or `task.Branch` — only `task.Name`.** Both fields are locked in at creation from the original regex slug; if you ever add code that re-derives the worktree path or branch from `Name` post-creation, the auto-rename will silently corrupt it. `task.Name` is a soft display string after creation.
- **The `claude -p` invocation MUST set both `--system-prompt` AND `--setting-sources ""`.** `--system-prompt` overrides (not appends) the default Claude Code preamble; `--setting-sources ""` is what actually disables MCP/hook loading from `~/.claude/settings.json`. Dropping either leaks tokens. `--strict-mcp-config` (with no `--mcp-config`) is the third leg — needed to suppress project-local `.mcp.json`.
- **Don't use `claude --bare`.** It's tempting (one flag instead of seven) but it disables OAuth/keychain auth and only works with `ANTHROPIC_API_KEY` — breaking users who login via the Claude.ai subscription.
- **`cmd.Dir = os.TempDir()` is required even with `--setting-sources ""`.** The `claude` CLI walks up from cwd to auto-discover `CLAUDE.md`; running from a worktree pulls the project's `CLAUDE.md` into context. Belt-and-suspenders with the settings flag.
- **Race guard is a single SQL CAS via `db.RenameIfName`, not check-then-set.** `runAutoRename` MUST use `RenameIfName(id, originalName, newName)` — a `Get`-then-`Rename` pair has a TOCTOU window where a concurrent manual rename gets clobbered. The CAS resolves the race in one `UPDATE … WHERE name=?`. If user types a name equal to the regex slug or the rename modal sets it back, auto-rename will still fire — cost of false-positive rename is low; adding a "was auto-named" boolean to the schema isn't worth it.
- **Goroutine inherits its parent process lifecycle.** TUI-initiated tasks fire `runAutoRename` inside the TUI process; if the user quits before Haiku returns, the rename is lost. Headless paths (HTTP API / MCP) run inside the daemon, so renames survive TUI restarts.
- **`AutoName` opt-in lives on each call site, not centrally.** Only set `AutoName: true` when the name was string-interpolated from `Prompt` — NOT for fork (`<src>-fork`) or multipart with attachment-derived name (the filename is already meaningful).
- **`llm.DefaultTimeout` bounds the WHOLE operation including the single retry — must comfortably exceed the claude CLI COLD-START tail under load, not just warm latency.** Each auto-name spawns a fresh `claude -p`, so it is effectively always a cold start; measured against this exact invocation, latency is ~3-5s warm, ~20s cold, and **>45s when the cold start races concurrent work** (the new task's own agent cold-starting, KB indexing, other live sessions). It was 30s → 45s → **120s**: the 30s and 45s caps each still hit `signal: killed` (the deadline SIGKILL-ing the process) — proven by the task-create→kill gap equalling the cap exactly (30.0s and 45.0s in the live logs). Costs nothing because the goroutine is fire-and-forget (a hung claude just idles one goroutine that long). If you shrink it, watch `[autoname] failed … signal: killed` in `~/.argus/daemon.log`; `TestDefaultTimeout_Bounds` pins both the 120s floor and a 5-min ceiling (the goroutine is unthrottled, so an over-large cap pins a goroutine for that whole window).
- **`GenerateName` retries the CLI ONCE on a non-zero exit, but NOT on a validation failure, and surfaces the FIRST attempt's reason on exhaustion.** A non-zero exit is transient (overload / usage-rate limit / budget blip) and retried after `retryBackoff` (a package var, zeroed in tests); a clean run whose output failed `sanitizeAndValidate` is terminal — retrying reproduces the same bad output. `generateNameOnce` returns `(name string, retryable bool, err error)` to keep that distinction. The loop keeps `firstErr` (never overwrites it): attempt 0 runs with the most deadline budget and carries the richest reason, while a retry can die bare (`exit status 1` / `signal: killed`) as the shared deadline closes — surfacing the last error would lose the diagnosis. Both attempts SHARE the caller's deadline (`runAutoRename` sets `llm.DefaultTimeout`); the retry is best-effort within it — fine because the transient cases fail fast, and a slow attempt-0 hang (not transient) correctly yields no retry.
- **`claude -p` writes RUNTIME errors to STDOUT, not stderr — `wrapRunError` folds stdout FIRST, then stderr if also present.** Budget-exceeded / usage-limit / overload errors print to stdout and exit non-zero with an EMPTY stderr (only flag-parse errors go to stderr). `cmd.Output()` returns the captured stdout in `out` even on error. The earlier stderr-only fold (commit f870331) logged every real failure as a bare `exit status 1` because stderr was empty — that was the bug behind "renames not working / name unchanged". Don't set `cmd.Stderr` (it would zero `ExitError.Stderr`); reason is truncated to 500 bytes (rune-safe).
- **The folded reason MUST be scrubbed of control chars (`scrubReason`) — it is untrusted and flows unescaped into logs.** `claude` may echo attacker-influenced prompt text; the reason reaches `uxlog.Log` (`%s`, newline-terminated per line) and slog's `TextHandler` (does not quote embedded newlines). An un-scrubbed `\n` would forge a second physical log line — a fake `[autoname] renamed …` audit record. `scrubReason` maps CR/LF/tab/ANSI-ESC/any control rune to a space (no collapsing) before folding. Don't remove it.
- **`--max-budget-usd` must stay well above the MEASURED per-call cost, not the original estimate.** A live call is ~1235 input + ~111 output tokens ≈ $0.0034 (Haiku 4.5, CLI v2.1.x) — ~17× the stale "~$0.0002 / ~150 tokens" the code once assumed. The cap is `0.05` (~15× headroom); the original `0.01` left only ~3× and a longer pasted prompt (URLs / issue bodies / JSON blobs) crossed it → `Error: Exceeded USD budget` on stdout → exit 1 → slug kept. Re-measure with `claude … --output-format json` before lowering it.

## Link Extraction

- **`osc8Re` must run BEFORE `ansiRe` in `stripANSI`.** OSC 8 hyperlinks embed URLs in escape sequences (`\x1b]8;;URL\x1b\\`). If `ansiRe` strips them first, the URLs are lost. The two-pass design in `internal/links/links.go:stripANSI` is intentional.
- **`tui/widget.AnsiRe`, `links/ansiRe`, and `sanitize/ansiRe` must all handle ST-terminated OSC (`\x1b\\`).** Claude Code uses ST (not BEL) for OSC 8 hyperlinks. Missing ST support causes URLs to splice with display text. The three regexes are intentionally separate: widget strips for display, links preserves OSC 8 URLs for extraction, sanitize strips for clean text.
- **Link extraction is shared between TUI and HTTP API.** `internal/links` exports `Link` + `Extract`; `internal/tui/links.go` adds the modal + `openURL` helper, and `internal/api/handlers.go:handleGetLinks` reuses the same extractor over the live ring buffer (or session log tail, capped at 1MB). Don't re-implement extraction in either client — both must produce identical results so users moving between TUI `ctrl+l` and the web "Open link" overflow item see the same set.
- **SGR sequences must strip to empty; cursor movement must strip to space.** Raw PTY logs contain cursor movement codes (`\x1b[5C`, `\x1b[1B`) that position text on different screen locations. Stripping these to empty merges unrelated text into URLs. `stripANSI` uses `ReplaceAllStringFunc` to distinguish: CSI ending in `m` → empty (preserves mid-URL colors), all else → space (prevents merging).
- **`bareLinkRe` must exclude `"`, backtick, `{`, `}`, `<`.** These are never valid in URLs per RFC 3986. Without exclusion, the regex matches through quoted/JSON URL data producing garbage entries in the link picker.
- **`hasValidHost` filters in-progress URLs (`https://gi`) by requiring a host with a real TLD.** The regex matches greedily as the agent streams output, so partial typing like `https://gi` would otherwise leak into the picker. Acceptance rule: IP literal, the literal `localhost`, or a DNS name whose final label is ≥2 chars starting with a letter (covers `.co`, `.museum`, and `xn--*` punycode). Don't tighten further with a curated IANA list — keeping the check syntactic avoids shipping (and updating) a 1500-entry blob.
- **`links.IsPR` is the single source of truth for the PR indicator; `Extract` stamps `Link.IsPR` so clients never re-derive it.** Both TUI pickers read `link.IsPR` and the web client reads the JSON `isPR` field — the JS must NOT pattern-match URLs itself, or TUI and web could disagree. `IsPR` matches on the path segment (`/pull/<n>` or `/merge_requests/<n>`), not the host, so it also catches GitHub Enterprise / self-hosted GitLab.
- **Both link pickers reserve a fixed `prLinkGutter` (2-col) left margin on every item row, and the modal-width calc must add it.** The PR glyph is painted into the gutter only for PR rows, but the gutter is reserved for all rows so PR and non-PR links stay column-aligned. If you compute `modalW` from the link display width without adding `prLinkGutter`, the widest PR link truncates a char early.

## Config file overlay (~/.argus/config.toml)

- **Precedence is `DefaultConfig() < DB (settings menu) < config.toml`.** The TOML file is an OVERRIDE layer applied last in `db.Config()` via `config.FileLoader.Apply`. Silent-failure mode to know: the settings menu writes to the DB, so any key ALSO present in config.toml masks the menu change — toggling it in settings appears to do nothing because the file wins on the next read. This is intentional (alacritty-style power-user layer) but surprising; don't "fix" it by reordering.
- **The overlay decodes the WHOLE Config, but several fields have no consumer yet — `ui.theme`, `ui.show_elapsed`, `ui.show_icons`, `ui.cleanup_worktrees`, and all of `[keybindings]` are loaded and persisted but read by nobody (grep confirms 0 production consumers; key routing is hardcoded, only one theme exists).** They're documented in the README with a ⚠️ "reserved" marker. When you wire one up, drop the marker — don't let the docs claim it works before the consumer lands.
- **The loader path is derived from the DB file path (`filepath.Dir(dbPath)/config.toml`), NOT from `$HOME` directly.** `Open()` wires it; `OpenInMemory()` leaves `cfgLoader` nil (a no-op), so in-memory/test DBs never read the real `~/.argus/config.toml`. To exercise the overlay in a test you MUST use `Open(filepath.Join(t.TempDir(), "data.sql"))` and drop a `config.toml` next to it — `testDB(t)` (in-memory) will not pick up any file.
- **Partial map entries in TOML zero the unspecified fields.** BurntSushi merges at the map level (a `[backends.foo]` adds `foo` and keeps `claude`/`codex`), but for a key that already exists it decodes into a FRESH zero struct — so `[backends.claude] command = "x"` wipes `claude`'s `prompt_flag`. Specify full entries for backends/projects you override. Scalar/struct fields outside maps overlay correctly (absent fields fall through). **Especially dangerous for `[projects.<name>]`:** a partial entry zeroes `path`/`branch`/`backend` for a project that the DB had fully populated, which can break worktree resolution — only put a project in config.toml if you mean to define it wholesale.
- **`ProjectSandboxConfig` IS reachable from config.toml despite having no `toml:` tags.** The parent `Project.Sandbox` field is `toml:"sandbox"`, so `[projects.x.sandbox]` decodes; the untagged inner fields match by lowercased Go name (`enabled`, `denyread`, `extrawrite`, `allowappleevents`) — NOT snake_case. The DB projects table is still the primary source; the file is an override on top.
- **`Apply` clones `Backends`/`Projects` before decoding** so the caller's maps are never mutated, even though TOML decode writes into the target map. `db.Config()` builds a fresh `cfg` each call so this is belt-and-suspenders, but the contract is relied on by the unit tests.
- **mtime+size caching gives live reload without fsnotify.** `readLocked` re-reads only when the file's modtime or size changed; an edit is picked up on the next `db.Config()` call. Parse/read/stat errors are surfaced via `Err()` and logged once per file-change (gated on `changed`) so a persistently broken file doesn't spam the log on every (frequent) `Config()` call. A broken file leaves the previously-resolved config in force (returns `base`), it does not blank the config.

## Claude session discovery (internal/claudesession)

- **The `~/.claude/projects/<dir>` folder name is the worktree's absolute path with EVERY non-alphanumeric char replaced by `-` — not just `/`.** `/`, `.`, and existing `-` all collapse to `-` (so `/Users/aaron/.argus/worktrees/ARGUS/x` → `-Users-aaron--argus-worktrees-ARGUS-x`, note the double dash from `/.`). The transform is lossy and one-directional; never try to decode it back. Verify empirically against the real dir when in doubt.
- **`claudesession.List` parses JSONL line-by-line with `bufio.Reader.ReadBytes`, not `bufio.Scanner`.** Conversation JSONL can contain multi-megabyte lines (tool results, attachments) that blow Scanner's default 64KB token limit; ReadBytes grows unbounded. Malformed lines and unreadable files are skipped, not fatal — a missing project dir returns `(nil, nil)` because a brand-new task simply has no sessions yet.
- **Metadata is reduced across all entries: last `ai-title` wins for the title, last `pr-link` for the PR, max user/assistant `timestamp` for ModTime (falling back to the file's mtime).** Title falls back to the first user `slug` (humanized), then `"(untitled session)"`. This single module is the intended source of truth for both the session switcher and the future `/clear` recapture fix — don't add a second JSONL parser.

## hera plugin contract (reliable pane delivery)

- **hera delivers messages via `POST /api/tasks/{id}/notify` + `DELETE /api/tasks/{id}/notify/{delivery_id}`, NOT raw `/input`.** The reliable notify service owns idle+focus gating and the submit CR — hera posts a delivery and cancels when the recipient acks. Any plugin that reverts to raw `/input` with an idle-gated CR loop reintroduces the original race.
- **`delivery_id` is caller-assigned; use the hera message ID.** It is alphanumeric + `-_`, max 128 bytes. argus deduplicates by `(taskID, deliveryID)` so re-posting is safe after a crash/retry.
- **`POST /notify` returns `state:"submitted"` (202) if the session was idle+unfocused at call time, else `state:"pending"`.** A pending delivery is retried on the daemon's 5-second idleWatcher tick. Both 200 (idempotent re-post) and 202 are success; 4xx requires a fix.
- **`DELETE /notify/{delivery_id}` always returns 200.** `cancelled:true` = was pending and removed; `cancelled:false` = already submitted or never registered. Both are OK — the message is durable regardless.

## hera.enabled settings toggle (M8)

- **`hera.enabled` defaults to TRUE — absent DB key ⇒ native Hera on.** This is the opposite of `kb.enabled` / `api.enabled` (both default false). `DefaultConfig()` sets `Hera: HeraConfig{Enabled: true}`; `db.Config()` only overrides when the key is present (`if v, ok := kv["hera.enabled"]; ok { cfg.Hera.Enabled = v == "true" }`). An absent key leaves the default intact.
- **config.toml overlay wins over DB for `hera.enabled` — the TOML `[hera] enabled = false` disables Hera even if the settings menu shows "Enabled".** Standard config.toml overlay precedence (DefaultConfig < DB < toml). Document this in UX if users report "toggle doesn't stick".
- **`cfg.Hera.Enabled` gates ONLY `SetHeraService` (the native `hera_*` MCP tool registration) now.** `daemon.go` wraps it in `if cfg.Hera.Enabled { … }`; disabling it before daemon start prevents the native hera MCP tools from appearing (and lets the external plugin's tools register instead). Toggling at runtime via settings requires a daemon restart to take effect (daemon reads config only at boot). It does NOT affect the TUI: the second tab is ALWAYS the native Hera view regardless of the flag (the legacy DAG-fallback page was deleted with depends_on).
- **`OnHeraToggle` in `SettingsView` is log-only now.** It no longer relabels or re-routes the second tab (the tab is unconditionally "Hera"); it only flips the DB flag, which the daemon picks up on its next start. There is no `heraTab2Label` function and no dynamic "Hera"/"DAG" label — `switchToHeraTab2` hard-sets the label to "Hera".
- **`stubStore.Config()` in tests should still return `config.DefaultConfig()`, not `config.Config{}`.** Not for tab routing (the tab is always Hera), but so other config fields (spinner style, etc.) are realistic and `Hera.Enabled` matches production default.

## OpenSpec archive workflow

- **`openspec archive <name> --yes` ABORTS but still exits 0 on a delta-vs-base mismatch.** It prints `… MODIFIED failed for header "…" - not found` / `… ADDED … - already exists` then `Aborted. No files were changed.` and returns rc=0 — a scripted `for` loop checking `$?` will silently skip the change. Detect failure by re-checking whether the folder actually moved (`test -d openspec/changes/<name>`) or grepping the output for `Aborted`, not by exit code. The abort is atomic (nothing partial), so just fix the delta and re-run.
- **Archive a backlog of un-archived changes in AUTHORING/merge order, not alphabetically.** `MODIFIED` replaces the whole requirement block and `REMOVED` deletes it, so the last-applied delta wins and every `REMOVED`/`MODIFIED` needs its target already present. Out-of-order folding either errors (target missing) or silently leaves the wrong generation in the base spec. Derive order from when each change first landed: `git log --diff-filter=A --format=%cI -- openspec/changes/<name>/proposal.md | tail -1`, sorted ascending.
- **Folding a backlog can yield an internally-contradictory base spec — audit for orphaned superseded requirements after archiving.** When a later change supersedes an earlier one by `MODIFY`-ing a *different* requirement (e.g. re-defining "Rail keybindings") instead of writing a `REMOVE` for the now-stale standalone requirement the earlier change `ADDED`, both survive the fold and contradict each other. `openspec validate --strict` does NOT catch this (it checks structure, not cross-requirement consistency). After folding, diff the base spec against current code behavior and delete the orphaned requirements by hand (this is what reconciled the stale `R`/`C`/`Ctrl+R`/`Ctrl+D`-bridging hera-view requirements vs the EOL-redesign nuke model).
- **A requirement's statement is parsed as the text up to the first blank line, and `validate` requires SHALL/MUST on that *first physical line*.** If you hard-wrap the statement so "SHALL" lands on line 2 (e.g. a lead-in clause ending in an em-dash on line 1), `openspec validate` fails with `ADDED "<name>" must contain SHALL or MUST` even though SHALL is present in the paragraph. Keep the SHALL on the first line — don't wrap before it.
- **Authoring drift to expect when folding old deltas:** a `MODIFIED` whose target was renamed/retired by later-merged work → drop or rewrite it; a `MODIFIED` for a requirement that is actually new (absent from base) → it's really an `ADDED`; an `ADDED` whose requirement a later change already put in base → drop the duplicate (keep base's newer version). `openspec archive` auto-creates new-capability specs with a `## Purpose\nTBD - created by archiving change <name>. Update Purpose after archive.` stub — fill it in the same PR.
