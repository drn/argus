## Task List & UI

- **The `l` / `L` keys are scoped per-tab. On the agent view, `l` opens the URL link picker (`openAgentLinks`). The task list itself does NOT bind `l`/`L`.** A new tab adding `l` would need an explicit `header.ActiveTab()` guard in `handleGlobalKey` to avoid shadowing; routing today relies on focus living on the active page's widget, which dispatches the key locally. (The retired DAG tab's `l`/`L` link/unlink keys are gone with depends_on.)
- **Numeric tab keys: `1` → Tasks, `2` → Hera, `3` → Settings.** The second tab slot (originally Settings, then DAG) is the native Hera view as of M6a — the enum constant was relabeled `TabDAG`→`TabHera` but kept its slot, so `2` routes to Hera. Any doc referring to "press 2 for DAG/settings" is stale.
- **Hera-spawned workers are HIDDEN from the Tasks tab by default; `H` toggles the reveal.** `buildRows` skips tasks where `isHeraSpawnedWorker(t)` (fed from the `task_meta` "hera" namespace via `App.readHeraRoles` → `tasklist.SetHeraWorkers`, predicate `meta:hera.role=worker`) while `hideHeraWorkers` is true (the default). They live in the Hera tab; `H` flips `hideHeraWorkers` and rebuilds. `H` is free both globally (`handleGlobalKey` only binds `q`/`1`/`2`/`3`/`?`) and in the tasklist (`j k n / s S a P r c`). Remote mode returns no "hera" meta rows, so nothing is hidden there — a safe degradation. Use `VisibleTaskIDs()` to assert what the tab actually shows.
- **Use `Header.SetNotice`/`ClearNotice` for async background operation progress, not blocking modals.** The header notice is a general-purpose left-aligned spinner + text area. Uses the progress spinner from `internal/spinner`. Progress tracking uses `atomic.Int32` + `QueueUpdateDraw` from background goroutines.
- **`showError` (the create/fork-failure modal) must be called AFTER `exitAgentView`, not before.** The error modal is a full-page swap (`AddPage`+`SwitchToPage("error")`), not an overlay, and `closeErrorModal` restores to the active tab's page (tasks/dag/settings) with `mode = modeTaskList`. The create-and-start failure callback first tears down any pending agent view, then calls `showError`; reversing the order leaves the daemon's pending agent page underneath and the mode/page state inconsistent on dismiss. Any key dismisses the modal (its `InputHandler` sets `closed` unconditionally).
- **Every modal close function must call `a.tapp.SetFocus(a.tasklist)`.** Without this, tview focus remains on the deleted modal widget, silently dropping focus-dependent key events (e.g., up/down in the task list). Tab switching (`1`/`2`/`3`) still works because it's handled in `handleGlobalKey` before focus-based routing, which masks the bug.
- **Filter-picker `Draw` must clamp the filter-field width to ≥1 before its right-truncation slice.** The shared filter-modal pattern (`taskswitcher.go`, `sessionpicker.go`, `fuzzylinkpicker.go`) computes `fieldW := innerW - 2`; on a terminal narrow enough that `innerW ≤ 2`, `fieldW` goes ≤0 and the cursor-keeping slice `runes[len(runes)-fieldW:]` indexes past the end → `slice bounds out of range` panic. Guard with `fieldW = max(fieldW, 1)`. Only the filter field needs it — `widget.DrawText` already no-ops on a non-positive `maxWidth`, so the item rows and their `[:textW-1]` truncation (guarded by `textW > 3`) are safe. Any new filter modal copied from these must carry the clamp.
- **Page wrappers with non-interactive child panels must guard `setFocus` in `MouseHandler`.** tview's default `Box.MouseHandler()` calls `setFocus(self)` on any click. Non-interactive panels (no `InputHandler`) silently steal focus, dropping all keyboard input. Fix: wrap `setFocus` in the page's `MouseHandler` to redirect focus to the interactive panel (e.g., `TaskPage` → tasklist). Symptom: user must switch tabs and back to regain keyboard control.
- **`rowTask` is `iota` (zero value) — never use `rowKind != 0` as a sentinel.** Use a boolean `hasPrev` flag when checking whether a previous row exists. The zero-value trap silently skips the intended code path for the most common row kind.
- **`SetTasks` must preserve cursor position across rebuilds.** Save the current row before `buildRows()`, then call `restoreCursor()` after. Without this, status changes via `s`/`S` keys appear to not work because the cursor jumps to a different row on refresh.
- **`restoreCursor` must filter by section (pinned / active / archive).** Cross-section project name collisions cause cursor jumps; `restoreCursor` takes a `rowSection` and uses `sectionAt` to reject matches in the wrong section.
- **`restoreCursor` must handle header/separator rows, not just tasks and projects.** `autoExpand` calls it after a section-toggle rebuild with the cursor possibly parked on a section header or separator. Falling through to `clampCursor` in those cases jumps the cursor away from the section you just entered.
- **`buildRows()` splits tasks into pinned / active / archived before grouping, in that order.** Pinned takes precedence over Archive when both flags are set, so a pinned-and-archived task surfaces in the Pinned section. The mutual-exclusivity invariant (at most one of Pinned/Archived is true) is enforced by `model.Task.SetPinned/SetArchived` — every callsite that mutates these flags (TUI key handlers, MCP `task_archive`, HTTP API `/archive`) must go through the setters or the DB will accumulate illegal states.
- **The Pinned section is always fully expanded — no `pinnedExpanded` / `pinnedProject` fields.** Pinning is an explicit "keep visible" action; auto-collapsing on cursor leave (the way Archive works) defeats the purpose. `autoExpand` deliberately does not toggle anything for `sectionPinned`.
- **`rowPinnedTrailingSep` is a dedicated row kind, not a heuristic.** The Active section has no header, so the boundary between Pinned and Active needs an explicit anchor in the row stream. `sectionAt` returns `sectionActive` on encountering it; plain `rowSeparator` rows are transparent (they lead INTO the Archive header below). Don't reuse `rowSeparator` for the Pinned/Active boundary or `sectionAt` will misclassify Active rows as Pinned.
- **The Pinned trailing separator is only emitted when Active has tasks.** Archive emits its own leading separator; if Pinned + Archive (no Active), emitting both produces a visible double separator.
- **`rowSection` constants are declared in visual top-to-bottom order** (`sectionPinned`, `sectionActive`, `sectionArchive`). Code that compares sections numerically (sort, range) gets sensible results; if you ever reorder, double-check there's no `if sec1 < sec2` reader assuming visual order.
- **Pinning has no HTTP API or MCP endpoint** — it is TUI-only. The PWA can read `task.pinned` from `/api/tasks` but cannot toggle it. Add `POST /api/tasks/:id/pin` + `mcp task_pin` if remote pin/unpin becomes a need; route both through `model.Task.SetPinned` to preserve the invariant.
- **`skipUpPastHeader` chains through stacked headers.** Moving up out of the archive section can pass through a (collapsed) header/separator pair; the loop keeps going until it finds a task or project row rather than handling a fixed chain depth.
- **Task-list previews must render the latest visible emulator lines, not `CellAt(x,y)` from row 0.** For Codex and any long-running PTY output, useful content often lives in scrollback or lower rows; replay logic must trim to bottom-of-history like `TerminalPane.paintEmu`.
- **Stopped agent → `StatusInReview`, not Pending.** Stopped means "needs human review".
- **Idle+unvisited tasks visually promoted to InReview.** Cleared on entering agent view.
- **`needsInput` does NOT downgrade on agent-view visit.** Unlike `idleUnvisited` (which clears the moment the user opens the task), the needs-input flag is recomputed every tick from a tail-scan of the session's PTY ring buffer. The icon self-clears only when the agent emits bytes that push the prompt marker out of the scanned window (i.e., the agent has acted on the user's answer). Opening the agent view to read but not respond intentionally leaves the icon urgent.
- **`agent.DetectNeedsInput` matches on Claude's selection-UI shape (`❯ 1.`), not prompt wording.** The same widget renders AskUserQuestion, permission prompts, and plan-mode confirmations — the U+276F + space + "1." signature is the common denominator and survives Claude wording changes. Do NOT add string variants like "Do you want to proceed?" — they're redundant with the shape match and reintroduce the wording-rot trap. To support Codex/other backends, add a *different* UI-shape marker, not a string.
- **`DetectNeedsInput` also fires on plain-text questions when the assistant's last response ends with `?`.** Heuristic: ANSI-strip the tail, locate the bottom-most input-prompt anchor, then read backward from there past blank and decoration lines for the last content line. If its final non-whitespace rune is `?` or `？`, treat as needing input. This catches "Want me to ship it?"-style turns where Claude stops generating without invoking the selection widget. Anchoring on the prompt is important — without it, hint lines below the input (e.g. "? for shortcuts", "· ← for agents") would dominate the search.
- **The input-prompt anchor is `❯`+NBSP (U+00A0), with `╭` kept only for old logs — current Claude Code draws NO box around the input.** The idle prompt renders as `❯` immediately followed by a non-breaking space; the NBSP is the discriminator vs `❯`+regular-space occurrences in transcripts (shell prompts in output, the selection UI's `❯ 1.`). When Claude dropped the `╭` box the `?`-heuristic went silently dead — every real session log tail had no `╭` while the prompt sat right there. If the icon stops firing on plain questions after a Claude Code update, diff the stripped log tail for a changed prompt signature first.
- **The backward walk from the anchor must skip Claude's decoration lines, not just blank ones.** A spinner-glyph timing line (`✻ Brewed for 57s`, `✶ Pondered for 12s` — verb varies, glyph set `·✢✳✶✻✽` is the stable shape) and sometimes a `────` horizontal rule sit between the last transcript line and the prompt. Without the skip, the timing line is the "last content line" and a genuine trailing `?` one line up is never seen. Key on the leading glyph (UI shape), never the verb wording.
- **Line-walking must split on bare `\r` as well as `\n`.** After ANSI strip, the live PTY stream separates visual lines with carriage returns (`…right?\r✻ Brewed for 57s\r\r❯ `); an `\n`-only walk treats the whole transcript tail as one giant line and lands on the wrong suffix.
- **Detection MUST run on ANSI-stripped text, not raw PTY bytes.** Claude colorizes each visible glyph in the selection UI separately, so the raw stream looks like `\x1b[...m❯\x1b[39m \x1b[...m1.\x1b[39m` — the literal substring `❯ 1.` never appears. `DetectNeedsInput` strips via `sanitize.StripANSI` before matching. The `claude_askuserquestion_with_interleaved_sgr_escapes` test fixture in `needsinput_test.go` pins this — keep it.
- **Claude renders the selection cursor in two paths.** Path A uses a literal space (`❯ \x1b[...m1.`) — stripped text becomes `❯ 1.`. Path B uses CSI cursor-horizontal-absolute (`❯\x1b[3G\x1b[...m1.`) to position the column — stripped text becomes `❯1.` with no space at all. Which path fires depends on layout context. The detector regex is `❯[ \t]*1\.` to cover both. A simple `strings.Contains(s, "❯ 1.")` will silently miss every Path B prompt — and that's the form AskUserQuestion uses most of the time.
- **`detectNeedsInput` reads from the on-disk session log, NOT from `SessionHandle.RecentOutputTail`.** In daemon-client mode the local ring buffer only fills after the TUI opens a stream connection for that session — i.e., after the user visits it. Reading the log file works for every running session unconditionally, which is the entire point of the icon (alert on tasks you have NOT looked at). One `io.ReadFull` of 16 KB per idle task per tick is well under a millisecond and avoids forcing every session to attach a stream just to be checkable.
- **Agent view's `AttentionBar` reads from `App.needsInputIDs`, not `idleUnvisited`.** It sits above `gitPanel` in the left column with proportion=0 / fixed-size=0 by default; `updateAttentionBar` calls `attentionBar.SetEntries` and the widget's `OnHeightChange` callback fires `ResizeItem` on the parent flex. The currently-viewed task is excluded so the bar only surfaces OTHER tasks blocked on a prompt. Do not skip the `forceRedraw` inside `OnHeightChange`; resizing a flex item is a layout change tcell's diff can mis-emit.
- **`needsInputIDs` is sticky across the idle gate.** Per-tick detection runs against `idleIDs` (sessions silent for ≥3 s), but Claude's prompt UI emits periodic animation bytes (cursor blink, spinner) that bump `lastOutput` and kick the task out of `idleIDs` for a tick or two. Without carry-forward the attention bar would oscillate — visible only when the task crossed back through the idle threshold. `detectNeedsInputSticky` re-checks any task in the previous `needsInputIDs` set against its log tail regardless of idle status; entries self-clear when the marker is no longer in the 16 KB tail (agent moved past the question) or when the task drops out of `runningIDs`.
- **Enter on completed task is a no-op.**
- **Daemon process appears as "argusd"** via symlink in `AutoStart`.
- **Task rename is display-only.** Worktree dir and branch unchanged. Use `db.Rename(id, name)` (not `db.Update`) — the modal captures a task pointer at open time, and a background `refreshTasksAsync` can replace `a.tasks` while the modal is open, orphaning the pointer. `db.Update` on the stale pointer overwrites concurrent field changes (e.g., agent exit setting status=Complete).
- **`ensureCursorVisible` must reset scrollOffset when all lines fit.** Check `totalLines <= visibleLines` → reset to 0.
- **`SettingsView.renderList` must clamp `scrollOff` to `max(0, len(rows)-innerH)` after cursor-based adjustment.** Without the clamp, window resize (maximize) leaves `scrollOff` stranded — the top settings rows become unreachable because the cursor is still within the visible range relative to the stale offset.
- **Tabs are 1=Tasks, 2=Settings.** All statusbar hints and test assertions must match.
- **Fork task `executeFork` must run worktree creation + context extraction in a background goroutine.** Git diff and session log reads are I/O that blocks the UI thread. The `QueueUpdateDraw` callback handles DB persistence and session start on the tview thread — same race-avoidance pattern as new task creation (use `refreshTasksLocal`, not `refreshTasksAsync`).
- **Task list filter must bypass global rune key handling in `handleGlobalKey`.** When `tasklist.Filtering()` is true, the `KeyRune` case must `break` before checking `q`/`1`-`4` shortcuts — otherwise typing those characters quits the app or switches tabs instead of appending to the filter.
- **`buildRows` must expand all projects when a filter is active.** Without `filterActive` check, filtered tasks in collapsed projects are invisible — the filter matches them but they're hidden behind a collapsed project header.
- **String slicing for backspace must use `utf8.DecodeLastRuneInString`, not `len()-1`.** `len()` counts bytes, not runes — slicing mid-rune corrupts multi-byte UTF-8 characters. Same applies to cursor column positioning: use `ansi.StringWidth()` for display width, not `len()`.
- **`drawTaskRow` cursor fill must not overwrite elapsed time.** The fill loop extends the highlight to the row edge, but elapsed time is drawn right-aligned first. Compute `elapsedCol` once and use it as the fill boundary — filling past it overwrites the duration indicator.
- **`moveCursor` must not fire `OnCursorChange` when clamped at boundaries.** When pressing up at the top or down at the bottom, `tl.cursor` is clamped to the same value — firing the callback triggers unnecessary git diff refreshes and preview fetches. Use a deferred guard comparing `tl.cursor != prev`.
- **The freelancers-only filter (`f`) is binding-derived, not task_meta-derived, and intentionally diverges from the `H` toggle.** `H` reads `task_meta` `hera.role=worker` (the sidecar stamped at spawn, never cleared); `f` reads `hera_bindings` live (ended_at IS NULL, kind in {coordinator,worker}), so a worker whose binding ended is immediately reclassified as a freelancer. `--remote` mode has no binding-query endpoint, so it falls back to the `readHeraRoles()` union (possibly stale — ended workers/coordinators stay "managed" until the next full-row refresh).

## Modal Forms (`handle*FormKey`)

- **Every `handle*FormKey` early-return on validation or DB save failure MUST set `form.done = false` before returning.** `HandleKey` only ever sets `done = true` (on Enter / Ctrl+S); it never clears it. Without the reset, the next keypress flows back through `Done()`, hits the same validation failure, and the user is stuck in an infinite submit loop with no way out except Escape. `projectform`/`backendform`/`scheduleform` all have this dance — copy it verbatim when adding a new modal form.
- **`Ctrl+R` (Tasks tab) prune is confirmation-gated (`openConfirmPrune` → `modeConfirmPrune`), and the re-entrancy guard lives on the GATE, not the worker.** `openConfirmPrune` returns early when the header notice is set (a prune is running) and skips the modal entirely when zero completed tasks exist (status note instead of a silent no-op); it counts completed tasks from `a.tasks` (already-loaded, includes completed/archived), NOT by calling `PrunePrepare` — `PrunePrepare`/`db.PruneCompleted` DELETE rows as a side effect, so they can never be used merely to count. Only `handleConfirmPruneKey`'s confirm branch calls `pruneCompletedTasks`. The `Ctrl+R` key + "prune completed" label are unchanged, so no help-modal/statusbar edit is required.

## Task Row Rendering

- **`drawTaskRow` gives the task name priority over the branch in width allocation.** The name is sized first (ignoring branch), then the branch fills remaining space. If branch is sized first (reserving space before name), narrow terminals squeeze the name to zero while showing a useless branch fragment.

## PR Review Indicator

- **The PR indicator cell only consumes width when the PR state is actionable; otherwise the name reclaims the space.** `drawTaskRow` advances the column by 2 (glyph + space) ONLY when `theme.PRGlyph` returns `ok` (awaiting-review / changes-requested / approved); for none/draft/merged-closed/unknown the cell is skipped and the name shifts left by 2. The earlier "always-reserved blank cell" was reverted on dogfood feedback — the wasted column read worse than the name shifting when a PR appears/vanishes. `maxNameW` derives from `col`, so it adapts either way.
- **PR state is ORTHOGONAL to the `in_review` status glyph — they coexist, never replace each other.** The status glyph reflects the manual workflow state (`pending`/`in_progress`/`in_review`/`complete`); the PR cell reflects a system-observed GitHub fact. A task can show both the `in_review` glyph and a PR-approved glyph simultaneously; the PR cell must never overwrite or substitute for the status glyph.
- **The coordinator indicator (`theme.IconCoordinator`) stacks AFTER the PR cell and is its own optional column — when both are present the order is `status → PR → coordinator → name`.** Both cells advance `col` by 2 only when present, so the four-cell layout is self-packing; tests assert the PR glyph at `prCellCol` and the coordinator glyph at `prNameCol` when they co-occur. The coordinator flag comes from `task_meta` `hera.role=coordinator` (NOT a `model.Task` field), so it is empty in `--remote` mode (the "hera" namespace returns no rows) — a safe degradation, never an error. Unlike hera *workers*, coordinator tasks are NOT hidden from the Tasks tab; the icon is purely additive. **Worker and coordinator sets come from ONE `App.readHeraRoles` call per tick** (it queries the "hera" namespace once and partitions by role) — do NOT re-introduce separate per-role readers that each re-query the same namespace.

## Persisting Task-List Edits

- **Status/pin writes that flip ONLY those columns MUST use the partial setters (`db.SetStatus` / `db.SetPinned`), never the full-row `db.Update`.** The `*model.Task` reaching these write sites can carry a *stale name*: a background autoname (Haiku) rename writes the better name to the DB ~12 s after creation, and `db.Update` rewrites every column (including `name`), so the write silently reverts the rename — the "task rename isn't working on some occasions" bug. This applies to four paths, with two different staleness windows: (1) `OnPin` and (2) `OnStatusChange` take the task list's cached `tl.tasks` snapshot, stale for up to a full refresh tick (the original, wide-window bug); (3) the daemon-mode reconciliation loop in `refreshTasksWithIDs` and (4) the `handleSessionExitUI` status flip both take a struct that was just `Get`'d but is still racy against the concurrent autoname goroutine in the straight-line window before the write (microsecond window). All four now route through the partial setters. **What still legitimately uses `db.Update`:** sites that write multiple columns at once (e.g. `startSession` stamping `SessionID`+`AgentPID`+`Status`, or the session-ID capture goroutine) — a single-column setter can't express those. Remote mode (`apistore`) mirrors the partial setters by re-fetching the authoritative row before writing, so it never sends a name of its own, and `apistore.SetStatus` carries the same same-status no-op guard as `db.SetStatus` to avoid re-stamping `ended_at`. The autoname path itself is independently guarded by `db.RenameIfName` (CAS); these setters close the symmetric hole on the other writers. **Out of scope (pre-existing, NOT converted):** the server-side status writers `daemon.transitionTaskOnExit` and the REST `handleSetStatus` endpoint still use full-row `db.Update`. They race the same microsecond window against autoname, but each does a fresh `db.Get` immediately before the write (narrowing it to straight-line code) and the daemon's flip is authoritative for the session-exit path — converting them would need multi-field setters and is tracked separately.

## Spinner Animation

- **Project status icon priority: actively running > in_review > idle in_progress.** If any task in a project is actively running (`running && !idle`), the project shows the spinner — even if other tasks are in-review. The variable is `hasActivelyRunning`, not the old `allInProgressIdle` inverse.
- **Spinner frame computation is time-based, not tick-based.** `updateSpinnerFrame()` computes `int(time.Now().UnixMilli() / interval) % frameCount` in `Draw()`. The 1-second tick loop is too slow for 100ms spinner frames. A dedicated `spinnerLoop` (100ms ticker) triggers redraws only when `len(runningIDs) > 0`.
- **`model.SetActiveSpinner()` is a package-level setter — not thread-safe for concurrent writers.** Currently safe because only the tview main goroutine (settings UI) calls it. If daemon or API ever sets it, add synchronization.
